Entry points: FO-6 part 3: `GET /api/front-office/retainers/:id/signing` (key `agent/retainer:show`, `@OwnOrAll("agent/prospect")`: status, "1 of 2 signed", signers' sides, names and moments, evidence hashes; no token, code or provider id); `POST /api/hooks/signing/:provider` (public, rate limited, the adapter verifies the body; PF-12's named use `front-office.signing.webhook`); `POST retainers/:id/send` now also creates the signing request (`signing/service.ts` `prepareRetainerSigning`); `signing/handlers.ts` `signingPort()`, `useSigningPort`, `useSigningMail`, `registerSigningHandler("CONSULTATION", …)` (FO-3c plugs in); `retainers/on-signing-completed.ts` `onSigningCompleted` (WON E_SIGNED once); event `signing.completed` (studio ports/events/signing.ts). Known gaps for later parts: a request sent before part 4 has no usable signing link (only the token's sha256 is kept and the column never changes); "Your signed agreement" is sent after the commit (a stop between them loses it: part 5's JobPort); `prospect.won` still carries `sealed_retainer_sha256: null` (sales/prospects.ts); the webhook re-serialises the parsed JSON until FO-6v mounts a raw body.
Tables: foSignatureRequest, foSigner, foSigningEvidence, foSigningHookReceipt (FO-6 part 3 writes them; part 1's schema).
