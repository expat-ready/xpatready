# Module card: api-platform (P-615)
Firms, staff and sign-in, settings, secrets, jobs, logs, complaints and message consent. Read this before editing these files; update it in the same PR when an entry point, invariant, table or test below changes (or say `Card unchanged: <reason>` in the PR body).

**Purpose.** `firm-scope.ts` the one firm filter; `identity/` tokens, staff and the guard (Cognito or local); `settings.ts` and `config/` typed firm settings and app configuration; `secret-box/` AES-256-GCM secrets; `jobs/` the one job runner (pg-boss); `observability/` the one logger, redaction, metrics, alerts; `web-address/` each firm's web address; `complaints/`; `messages/consent/` the consent store; `audit/`; `firms/` self-serve sign-up to a no-card trial (PF-5); `terms/` pending terms and their acceptances (PF-5t); `keep-period/` the keep-period table's read and the firm's own number for closed client files, a reminder with a warning below the College's 6 years, never a lock (AUD-5; `ports/keep-period.ts` holds the table, the port and its fake); `billing/` BillingPort's Stripe adapter (`ports/billing.ts` holds the port and its fake); `entitlements/` plan limits (PF-15 part 1a): `limits.ts` PgEntitlements, the real EntitlementPort (`ports/entitlement.ts`; seats from `platform_plan.seats_limit`, cases and storage from `platform_plan_limit`; null Unlimited, 0 none, no row or no live plan 0; read through the definer `platform_entitlement_limit`), `seatsUsed`; `storage.ts` StorageWatch (the storage-over mark, the day-one emails, the daily job) and EntitledFiles (the FilesPort uploads get: a new key refused 409 while storage is hard); `settings/offices/` a firm's offices, each with its own time zone, hours and closed days (PF-18a; OfficeClockPort's real adapter `OfficeClock`, `ports/offices.ts` holds the port and its fake).
**Owner area.** platform module rows PF-* (Unconfirmed: no lane map in code).
**Entry points.** `/api/platform/complaints` (PF-21w; PF-21v adds `GET handlers`); `/api/platform`: `GET me`, `POST session/local`, `POST staff/invitations`, `POST staff/invitations/batch` (PF-4c: 1-20 rows, flags per row, one seat check), `PATCH staff/:id/roles`, `POST staff/:id/deactivate`, `PUT staff/:id/credential`; PF-4b: `GET staff`, `GET staff/:id`, `GET licences`, `GET|PUT me/account`, `GET settings/two-step`, `POST session/callback`, `POST session/sign-out`, `POST staff/:id/sign-out-everywhere`, `POST staff/:id/reset-two-step`, `/api/public/invitations/:token` (+ `/accept`), `requireStepUp` (401), `MAIL_PORT`, `IDENTITY_ADMIN_PORT`; PF-6r: `GET roles` (the six starter roles, each key with class and scope); PF-19b: `MESSAGE_PORT`, `MESSAGES_MAIL` (MailPort over MessagePort: booking mail), `GET /api/demo/platform-inbox` (demo only, with attachments); `firmScope(firmId)`, `PlatformJobs` (`jobs.handle`), `CONSENT_PORT`, the guard of `/api/platform/*` and `/api/front-office/*`; AUD-5: `GET keep-periods`, `PUT keep-periods/closed-client-files`, `KeepPeriods` (KeepPeriodPort); `/api/public` (PF-5, open doors): `GET plans`, `POST signup`, `POST signup/verify`; PF-18a: `GET|POST /api/platform/offices`, `PATCH /api/platform/offices/:id`, `OFFICE_CLOCK` (OfficeClockPort), `zoneForProvince(code)`; PF-5t: `GET me/terms`, `POST me/terms/accept`, `GET terms/acceptances`, `TERMS_GATE` (the guard's 428 TERMS_PENDING); PF-15: `StorageWatch`, `EntitledFiles`, `PgEntitlements`, `planLimitReached` (409 PLAN_LIMIT_REACHED with metric, limit, used and upgrade path), the job `platform.entitlements.storage_daily` (12:15 Toronto).

**Invariants (set by).**
- Every read and write of a platform or front-office table goes through `firmScope(firmId)`; another firm's row is "not found" (PF-3, contracts §0.2; P-559).
- The database walls it (PF-12): the API connects as `xr_app` (owns no table; it refuses to start otherwise), each query runs as its caller's firm (`firm-scope.ts`: the guard's firm, a door's resolved firm, a job's firm; none reads nothing); crossing firms only through `asBypass(use)` for a use on `BYPASS_USES`, each use logged. Every new `platform_*`, `fo_*`, `money_*`, `msg_*`, `auto_*`, `plat_complaint*` table ships its forced policy in its own migration.
- Sized for about 100 firms in one process (P-562).
- Two-step sign-in is required for every staff member (P-567).
- The audit trail is append-only, enforced at the database since AUD-1a (UPDATE, TRUNCATE and any DELETE outside the demo reset's Sample lines refused); demo reset deletes only demo lines, never a platform line (P-571 (1)).
- When role change, invitation accept or firm signup gives a role that brings money keys, it writes one `platform.staff.money_keys_granted` line through `identity/money-line.ts` only, in the caller's transaction (PF-6b ruling 2 (b), PF-6m, PF-6m2). An invitation is accepted only while its inviter is active and may still give every role invited; otherwise 410 and `platform.invitation.refused_inviter` (PF-6m2).
- Personal data never reaches a system log: redaction at the logger (PF-23, NFR5-14).
- A job's key is its pg-boss id: one key never queues a second job (PF-14).
- The consent store is the only writer of the `msg_` tables, inside the caller's transaction (PF-19a, P-584).
- Values for experts to set are labelled Sample, never guessed (P-170).
- One office → the firm's own zone, hours and closed days; office rows exist only once a second office is added, and that add writes the first office from the firm's settings; an office is never removed here (PF-18a, AG-1-74, AG-16-68).
- A sign-up's password goes to the identity provider only: never in a table, log, audit line or answer; the sign-up door answers the same whether or not an email is known (PF-5, P-566).
- A person with a current terms version to accept (privacy notice: each person; terms of service and data processing: an Owner for the firm) gets 428 TERMS_PENDING on every guarded route but `GET me`, the two `me/terms` routes and sign-out (PF-5t; wording Sample, Unconfirmed: no counsel).
- Firms' billing goes through BillingPort only; CI and lanes use its fake or recorded Stripe answers, never a live call (PF-5, contracts §0.3).

**Do not.**
- Query a firm table without `firmScope`.
- Cross firms without `asBypass` and a named use, add a firm table without its policy, or set `app.firm_id` or the role on a connection outside `firm-scope.ts`.
- Log a name, email or other personal value; log record ids.
- Start a second job runner or logger.
- Add a package outside STANDARDS §1's gate.

**PF-19b part 2 (messages: SES, bounces, one-click unsubscribe).** Entry points: the email adapter by setting (`local`, or SES when PLATFORM_ENVIRONMENT is test/production with PLATFORM_SES_REGION and a verified sender; fails closed without one), `GET|POST /api/public/unsubscribe/:token` (one-click, ConsentPort.withdraw via UNSUBSCRIBE, email marketing only), `POST /api/public/messages/ses-notices` (SNS, signature checked first; outside local only from a configured topic); `GET /api/demo/platform-inbox` also lists the List-Unsubscribe headers. Invariant: email reaches SES only through the SES adapter; CI and lanes use recorded SES answers, never a live send; an SNS notice is read only after its signature verifies.
