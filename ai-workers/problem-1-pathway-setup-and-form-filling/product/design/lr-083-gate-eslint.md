## Technology gate record: eslint 10.14.0 + typescript-eslint 8.72.2 + eslint-plugin-react-hooks 7.1.1, report-only

Versions read 28 Nov 2026 on the npm registry (`npm view <pkg> time`), each at least two weeks old: eslint 10.14.0 (30 Oct 2026), @eslint/js 10.0.1 (6 Feb 2026), typescript-eslint 8.72.2 (9 Nov 2026), eslint-plugin-react-hooks 7.1.1 (17 Apr 2026), globals 17.14.0 (1 Nov 2026). Installed with `npm install -D --save-exact --before=2026-11-14`, so every transitive package is from before 14 Nov too. Dev dependencies only; nothing reaches the built app.

* **Problem.** LR-083 ([C1] "Give Claude something it can run that comes back pass or fail"): main has no lint for the studio's ~2,440 TypeScript/JavaScript files. `tsc` catches type errors, not unused variables, stray expressions, `var`, or React hook misuse (`react-hooks/*` found 285 such places in `web/src` on main). STANDARDS §7 asks for lint; nothing runs it.
* **Options weighed.** (1) ESLint flat config with typescript-eslint (non type-aware) and the React team's hooks plugin: the common stack for TypeScript + React, MIT, with built-in **bulk suppressions** (ESLint 9.24+) so the 4,091 findings on main are held and only new ones show. (2) typescript-eslint type-aware (`recommendedTypeChecked`): finds more, but builds a TypeScript program for every file (minutes on this tree); later, through this gate, if wanted. (3) Biome (one Rust binary, fast): no React hooks rules of equal depth and no bulk-suppression file; a second toolchain beside `tsc`. (4) oxlint: fast, but its suppression story is per-line comments, which would touch ~1,000 files. (5) Nothing: keeps the gap. Chosen: (1).
* **Integration and upkeep.** `studio/eslint.config.mjs` (recommended rules of @eslint/js and typescript-eslint on every tracked .ts/.tsx/.mts/.cts/.js/.mjs/.cjs; react-hooks `recommended-latest` on `web/src`; browser globals there, Node globals elsewhere). `studio/eslint-suppressions.json` holds every finding on main at `a3466b5c4` (1,007 files; generated once with `--suppress-all`, never by hand). CI: `.github/workflows/lint-report.yml` on PRs that change the studio or the workflow; `npm ci --ignore-scripts`, then `npx eslint . --pass-on-unpruned-suppressions`, `continue-on-error`, the output in the job summary; no Mergify condition or ruleset names it. Measured here: the whole tree in ~75 s (Node 22, 2 cores); a new finding exits 1 (probe file with `any`, `var` and an unused variable gave 3 errors), main exits 0. Upgrades only through this gate, all five packages together; after a held finding is fixed, `npx eslint . --prune-suppressions` shrinks the file.
* **Edit-loop hook (the second half of the row).** Timed before wiring, as the row's Done when asks: one file takes 0.64 s (14 lines, `web/src/main.tsx`), 0.71 s (206 lines, `engine/resolver.ts`), 0.95 s (1,289 lines, `api/src/studio.ts`) and **2.10–2.24 s** (1,135 lines, `web/src/runtime/questionnaire.tsx`; three runs; the React Compiler rules of react-hooks 7 are the cost). The largest React files are over the 2 s budget, so **the hook is not wired** in this PR. Options for the follow-up (tech lead's choice): wire it for `api/`, `engine/`, `tests/` only (all under 1 s measured), or run ESLint's own cache (`--cache`) in the hook and time again.
* **Data and licence.** Reads our source files only; no network at run time (packages come from the npm registry at `npm ci`, as for the rest of the studio). No personal data. MIT licences, CI and developer tools never shipped in the app, so no licence duty reaches the product (Unconfirmed: no counsel). Cost US$0 (hosted runner on a public repository).
* **When to reconsider.** After 10 clean PR runs, a later PR may make the job blocking (drop `continue-on-error`) and add it to a required check. Drop a rule that raises more than about one false finding a week (with its reason here). Revisit type-aware rules or Biome/oxlint if the full run passes 3 minutes.
