## 1. Root cause (5 lines)

1. **The rule existed but was lost from the start read.** P-388 (DECISIONS, 7 Nov): "the Lead starts a fresh `lead/<today>` branch from `origin/main` every day". It is in `P/WAY-OF-WORKING.md:111` (main) but the one-page `P/RULES.md:123` (main and HEAD) keeps only "No prompt-waiting call while the founder is away"; the branch half was dropped. AGENTS rule 9 says Leads start from RULES + STATE, and STATE "Do first" (lead4 `P/STATE.md:8`) has no branch step.
2. **No machine noticed.** `T/lane.sh:28` says `lead` for any `lead/*` branch, whatever its age (lanes get a 24 h staleness check, QA-181, `T/lane.sh:54-62`; the Lead gets none). `T/session-start.sh:15` compares HEAD only with `@{upstream}`; `lead/2026-11-07-lead31` has no upstream configured ("fatal: no upstream configured"), so the hook printed nothing. The OS-11 fix (#3506 check-tools-fresh; `tools-on-main.sh`) is not on main: LR-032 says "Intended", and `tools-on-main.sh` exists only on the unmerged `origin/claude/blissful-goldberg-u5ik45-measures` (`73e2df6b6`).
3. **Switching was costly, so Leads avoided it.** A checkout rewrites `.claude/skills/*` and `.claude/settings.json`. These are protected paths: they need a permission prompt (memory `no-prompting-calls-unattended`, 7.4 h stall on 6-7 Nov), and this sandbox denies writes to them. The copy is half-switched right now: `MM` on settings.json and 4 skills, with 6,107 staged adds and 1,535 staged deletes.
4. **Each hand-over kept the branch.** Standbys run in the same copy (`use_worktree: false`, lead skill line 55). The hand-over steps are current_lead → STATE → "take over now", with no branch step. 195 commits changed the `current_lead:` line on lead31 since 11 Nov. `T/current-lead.sh` reads STATE from `origin/lead/*`, so lead31 kept working as the records home.
5. **Records still reached main from side branches, so the gap stayed hidden.** Examples: `origin/lead/2026-11-24` ("fresh Lead branch from main, records carried over from lead31"), `lead3-records`, `lead3-records2` (based on main, 0 ahead). These met P-388 in letter, but the working copy (hooks, skills, tools) never moved. On 20 Nov the memory note `read-config-from-origin-main` treated the symptom ("use git show origin/main") rather than recutting.

Branch history (reflog): `lead/2026-11-07-lead31` was "Created from HEAD" on 7 Nov 17:19 IST, from `lead/2026-11-07-lead30`, not from origin/main. Four lead branches were cut that day (lead26, lead29, lead30, lead31). Main was last merged in on 11 Nov 13:15 IST ("lead: merge main", merge-base 11 Nov 07:21 UTC). The board/G-1..G-5 branches were merged into it on 15 Nov. Resets followed on 15 and 22 Nov. The last checkout was 14 Nov. Today: 7,638 commits behind, 3,187 ahead.

## 3. Best place for the Lead to work

| Option | Verdict | Why |
|---|---|---|
| A. On `main` itself | No | Records reach main only by PR. Pushes to main are refused (`.githooks/pre-push:14`, P-87), Mergify queues every PR (`P/WAY-OF-WORKING.md:25`), and a ruleset is planned (P-845). A local `main` that only fast-forwards is fine to read from, but nothing can be committed on it |
| B. A dated `lead/<date>` branch recut from origin/main daily and at every hand-over (P-388) | **Yes, with two fixes** | Already the rule, and `lane.sh whoami` accepts it. The fixes: (1) a machine check of age and distance (section 4), not prose; (2) do the recut only in a founder-typed turn, because it rewrites `.claude/`. Alternatively, recut with zero `.claude/` change only when main did not touch `.claude/` (compare `git diff --quiet HEAD origin/main -- .claude`) |
| C. Records in a separate worktree, tools always run from an origin/main checkout | **Use this as the safety net for B** | `demo-main` already sits detached on origin/main and is current. Running `lead-watch.sh` and other reports from there (or via `git show origin/main:<tool>`) removes the stale-tool class of error even on the day B slips. Claude Code worktrees: `claude --worktree <name>` gives each session its own checkout (quoted in `P/design/claude-code-devops-research-2026-11-16.md:16`). Limit: hooks and skills still load from the project dir at session start ("Skills and hooks that changed take effect in the next session", `T/session-start.sh:17`), so C does not fix hooks; only B does |

Recommendation: **B plus C.** The Lead copy sits on `lead/<today>`, cut from origin/main at the first check of each IST day and at every hand-over (a new Lead's first action). Reports run from main's tools. Never merge main into a lead branch (P-388). If a recut would touch `.claude/` while the founder is away, park it for his next typed turn and run tools from `demo-main` meanwhile.
