# Claude Code for DevOps and end-to-end engineering: what teams do, what we do, and Devin
Research note, 16 Nov 2026. Read-only look at the repository; no repository file was changed. Official Anthropic pages carry no publication date, so they are cited "read 16 Nov 2026" (they are the live docs). Practitioner write-ups carry their own dates where the page gave one.

Plain-words glossary: "headless" = Claude Code run by a script with nobody typing (`claude -p "task"`); "hook" = a small script that always runs at a fixed moment (for example before any merge command) so a rule is enforced by machinery, not by asking the AI nicely; "subagent" = a helper AI with its own fresh memory and a narrow job; "MCP server" = a plug-in connection from the AI to an outside tool (GitHub, a database); "worktree" = a second working copy of the code so two AI sessions never overwrite each other; "CI" = the automatic checks that run on every change.

## Part A. How teams use Claude Code (2025-2026)

1. Headless mode. `claude -p "..."` runs once, prints the answer and exits with a pass/fail code, so scripts can branch on it. Output can be plain text, JSON (includes cost per run) or streamed. Options: restrict which tools it may use (`--allowedTools`), a stricter "deny anything that would ask" mode (`dontAsk`, `--permission-prompts none`), and `--bare` for repeatable runs on CI machines (it skips local hooks and settings; Anthropic says it will become the default for `-p`). A `--max-budget-usd` cap stops a run at a dollar ceiling. Source: https://code.claude.com/docs/en/headless (read 16 Nov 2026).
2. GitHub Actions (anthropics/claude-code-action, current line "v1"). Two modes: answers when someone writes @claude on a pull request or issue, or runs a stated task on any event or schedule. Ready-made workflow for pull-request review; skills in the repo's `.claude/skills/` can be run from it. Cost controls named by Anthropic: `--max-turns`, workflow timeouts, GitHub concurrency limits, concise CLAUDE.md. Security: the person triggering needs write access; bots are rejected unless listed; on public repos, secrets are withheld from fork PRs so review runs only on same-repo branches. Sign-in options: API key, subscription token, or keyless sign-in tied to GitHub. Source: https://code.claude.com/docs/en/github-actions (read 16 Nov 2026).
3. Managed "Code Review" (Team and Enterprise plans only). Several AI agents read each pull request, a verification step removes false alarms, findings arrive as ranked inline comments plus a check; it never approves or blocks. Billed on tokens through "usage credits"; there is no flat price per review; you set a monthly spend limit; "after every push" multiplies cost by number of pushes; drafts and forks are skipped. Source: https://code.claude.com/docs/en/code-review and https://code.claude.com/docs/en/code-review-costs (read 16 Nov 2026). Anthropic's own comparison table lists the alternatives: this managed service, `/code-review` run by you, Ultrareview in a cloud sandbox, Claude in your own CI, or your own reviewer as a subagent or skill.
4. Hooks. Anthropic: hooks "give deterministic control" so actions "always happen rather than relying on the LLM"; used to enforce project rules, format code, notify, block commands. Also a cost tool: a hook can trim a 10,000-line log to the error lines before the AI reads it. Sources: https://code.claude.com/docs/en/hooks-guide and https://code.claude.com/docs/en/costs (read 16 Nov 2026). Practitioner: Intercom (19 Mar 2026) uses hooks to force every pull request through one approved skill, block edits on already-merged branches, and log events; also a background agent that watches CI and a "flaky test fixer" whose rules forbid skipping the test as a fix. https://ideas.fin.ai/p/how-we-use-claude-code-today-at-intercom
5. Subagents. Used to keep noisy work (running tests, reading logs, research) out of the main conversation and to cheapen it with a smaller model (`model: haiku` for simple helpers). Source: https://code.claude.com/docs/en/costs and https://code.claude.com/docs/en/common-workflows (read 16 Nov 2026). Anthropic warns agent "teams" use about 7x the tokens of a normal session.
6. MCP servers vs command-line tools. Anthropic says command-line tools (`gh`, `aws`, `gcloud`) are more economical than MCP servers because they add no per-tool listing; disable unused MCP servers. https://code.claude.com/docs/en/costs (read 16 Nov 2026).
7. Skills and slash commands. Long, situational instructions belong in skills (loaded only when used), not CLAUDE.md; keep CLAUDE.md under about 200 lines. Skills run in headless mode and in GitHub Actions by writing `/skill-name` as the prompt. https://code.claude.com/docs/en/costs and https://code.claude.com/docs/en/headless (read 16 Nov 2026).
8. Permissions and sandbox. Allow and deny lists in settings; Anthropic's engineering post (20 Oct 2025) says OS-level sandboxing (files limited to the working folder, network through a filtering proxy) cut permission prompts 84% in its own use. https://www.anthropic.com/engineering/claude-code-sandboxing
9. Worktrees for parallel work. `claude --worktree <name>` gives each parallel session its own checkout and branch so edits cannot collide; a background-agent view monitors them. https://code.claude.com/docs/en/common-workflows (read 16 Nov 2026).
10. Scheduled and unattended runs. Four options: Anthropic cloud "routines" (run with your computer off, can start on a GitHub event), desktop scheduled tasks, GitHub Actions cron, and `/loop` inside one session. Tip from Anthropic: the prompt must say what success looks like and what to do with results, because the run cannot ask questions. https://code.claude.com/docs/en/common-workflows (read 16 Nov 2026).
11. Cost control (Anthropic's own numbers). Average about US$13 per developer per active day, US$150-250 per developer per month, under US$30 per day for 90% of users. Biggest levers: clear the session between tasks, pick Sonnet not Opus for routine work, lower "effort", plan mode before big changes, keep sessions short (every turn re-reads the whole conversation), and idle sessions on timers still spend. Per-run cost shows in JSON output; org-level limits in the Console or admin settings. https://code.claude.com/docs/en/costs (read 16 Nov 2026).
12. Practitioner cautions about unattended runs (secondary, treat as advice not measurement): start with review, triage, summaries and low-risk fixes, not auto-merge; headless runs guess when confused; give only the model key as a secret, cap turns, never rely on prompt text to forbid something (enforce with permissions), turn off AI review for fork PRs (prompt-injection risk); one write-up estimates US$0.02-0.10 per review and US$0.20-1.00 per auto-fix with Sonnet (undated page). https://www.deployhq.com/blog/running-ai-coding-agents-cicd-headless-mode-claude-code-codex-gemini ; a general search of how-to posts (https://dev.to/raxxostudios/headless-claude-code-5-things-i-run-from-my-github-actions-1mm4) found mostly tutorials, not measured team results.
13. Forward-deployed engineering. I found no credible write-up tying Claude Code to that role specifically; practices above (a repo-held CLAUDE.md, skills per customer workflow, hooks, MCP connections to customer tools) are what the sources describe. Say "unconfirmed" if this is quoted.

### (2) The gaps that matter most, with fix and cost

1. No independent AI reviewer that runs on every pull request in GitHub itself. Today review depends on the builder's session running the review agent, and on Devin as an outside commenter. Fix: add one GitHub workflow using anthropics/claude-code-action with the `/code-review` skill, same-repo branches only, `--max-turns` set, a timeout, and a concurrency limit. Cost: about half a day of Tech lead time to set up; then per-review token cost (one practitioner estimate US$0.02-0.10 per review on Sonnet, undated and unverified; Anthropic publishes no flat price); GitHub machine minutes are free because the repo is public. Needs an API key or subscription token stored as a GitHub secret (founder decision, a credential). Risk: duplicates Devin's job; see Part 3.
2. Nothing a human can run unattended and cheaply to check Claude's own work (no `claude -p` in scripts). Fix: two small scripts: a "diff reviewer" (`git diff main | claude -p ...`) and a nightly "are the records still true" check, both with `--bare`, a capped tool list and `--max-budget-usd`. Cost: a few hours; pennies to a few dollars per run, visible in the JSON output.
3. No hook that trims noise before the AI reads it. Test and CI output is long; the rules say "judge by exit code" but nothing enforces short output. Fix: one pre-command hook that keeps only the last lines or failures of suite output (Anthropic's own example). Cost: about an hour; saves tokens on every build session, which is the stated biggest cost driver. 
4. Cost is measured by weekly plan percent, not per task. Fix: record the `total_cost_usd` from headless runs, and per-PR token cost in the PR body; add a spend limit in the Console if an API key is used. Cost: small; gives the "what did this row cost" number the founder rules ask for.
5. Safety review of the sandbox setting and bare mode for any unattended run (UNKNOWN today). Fix: confirm sandbox on in builder copies and use `--bare` plus `dontAsk` for every scripted run so a teammate's local hook or setting cannot change results. Cost: under an hour.

Not gaps: MCP (command line is cheaper), worktrees, hooks for guard rails, skills, deny rules.

### (3) Devin

What the repo says Devin does here:
- Outside checker, report only (P-146, 29 Oct; P-182, 30 Oct; P-188, 30 Oct "Devin weekly"): reviews pull requests automatically and, on demand, runs prompts D1 (look and usability walk), D4 (capability gap check before milestone gates), D5 (3-4 hour explorer), pasted by the founder from `product/inbox/DEVIN-PROMPTS.md`; it writes one findings file on a `devin/*` branch into `product/inbox/`, changes no code, opens no pull request. D2 (security) and D3 (Linux testing) are parked until production (P-197).
- It earns its keep as a bug finder: Devin's review comments are cited as the reason for fixes in `.github/workflows/pr-rules.yml` (line 37, review on #1834), `ci.yml` (line 363, #1337), `tools/label-guard.sh` and `tools/current-lead.sh` (#1136), `tools/check-select-suites.sh` (#1337).
- Decision P-354 (5 Nov): "Devin does not replace Claude lanes" because Opus review and qa run on Claude; it stays on PR reviews. P-182 sets a stop rule: a charter ends if after two rounds fewer than about half its findings are real.
- Cost: THE REPOSITORY CANNOT TELL whether the team pays Devin. No decision, record or workflow states a plan, price or invoice; the D1/D5 prompts say "US$0" but that means no AI-model spend inside the app's own tests, not Devin's own fee. Nothing in `.github/` calls Devin (it is a GitHub app, so a workflow file would not show it).
- What the public sources say (secondary, unverified against the pricing page): Devin's docs list Free $0, Pro $20/month, Max $200/month, Teams from $80/month (full seat $40) with prepaid "on-demand credits" (https://docs.devin.ai/admin/billing/self-serve.md, no date on the page). Cognition's 14 Apr 2026 post (https://www.cognition.com/blog/new-self-serve-plans-for-devin) is reported to say Devin Review is free on open-source repos and, elsewhere, a 2-week trial then usage-based billing; the docs say public GitHub PRs can be reviewed free at devinreview.com. This repository is public, so Devin Review on it may be free, but this is NOT confirmed. Plan-level billing for Pro/Max is "not specified" in the docs.

Does Claude Code cover the same job? Mostly yes for the review and testing part: Claude Code on a PR (claude-code-action or `/code-review`) reads the diff and surrounding code; skills such as journey-test and the screen-breaker agent already walk the app like a person; headless runs can do the weekly gap check. What Claude Code does not give: a second, different model family's opinion (the value of an outside check; the repo's own incident table shows Devin found real defects), and the Anthropic managed Code Review needs a Team or Enterprise plan (the repo cannot tell which plan the account is on).

Recommendation: KEEP for now, narrow it and measure it; do not replace yet.
1. Founder checks in the Devin account settings (not the repo) what is billed: plan, credits used last 30 days, and whether Devin Review on this public repo draws credits. That one number decides everything.
2. If it costs real money: keep only automatic PR review plus D4 before each milestone gate; stop D1 and D5 runs, because skills the team already has (journey-test, qa) cover walks.
3. In parallel add Gap 1 above (Claude reviewer in GitHub) as a trial for two weeks and compare real findings per review against Devin's, using P-182's own rule (about half of findings real). Replace Devin only if Claude finds what Devin finds and the independent-model argument is judged not worth the fee. If Devin is free on the public repo, keep it: zero cost for an independent pair of eyes.
