The flow, from a lane's brief to merge

The real order of one lab or product change today. Each step names where it lives and where the practice comes from. "P-" rows are the founder's decisions in DECISIONS.md; C-keys are the citations in the lab register.

  1. Decision. The founder decides; the tech lead writes it as a P-row. Lives: DECISIONS.md. Source: house rule (AGENTS rule 2).
  2. Row with a pass-or-fail "Done when". One register or backlog row per item. Lives: design/lab-register-2026-11-27.md, BACKLOG.md. Source: C1 "Give Claude something it can run that comes back pass or fail."
  3. Brief with a stop rule. The Lead writes the lane's brief; brief-check.sh --brief refuses one without a stop rule. Source: the loops article (trigger, stop condition, primitive), LR-121.
  4. Lane starts. Only in a turn the founder typed (app limit: 10 starts per message); hooks check the lane and the model. Lives: lane-preflight.sh, agent-model-guard.sh.
  5. Build. /next: branch from origin/main, build, tests per business rule, one PR per row (≤800 changed lines unless an exception is granted). Lives: next and screen-build skills. Source: small batches (DORA), P-610 size rule.
  6. Independent review. A fresh-context reviewer agent posts "Approve <head sha>" or changes, by REVIEW.md; a breaker agent attacks screens. Source: C16 "Separating the agent doing the work from the agent judging it", C14 sub-agents, Claude Code Review docs (C6).
  7. Checks on the PR. ci (required), fast route, pr-rules (fail closed), guards (required on pipeline paths), pr-suites, walks, label-guard, review-rounds. Lives: .github/workflows/. Source: required status checks (GitHub docs, C19).
  8. Lead read (pipeline paths only). The Lead posts "Lead read the diff: <full sha>"; lead-read.yml accepts only the Lead's line and a full sha. Source: house rule (P-423 paths, full-sha rule 27 Nov). Practice elsewhere: code owners plus an automated approver.
  9. Label. review: approved needs the Approve line (and the Lead read where owed). The queue gate labels ordinary PRs; the Lead labels records and risky PRs. Lives: label-guard.yml, queue-gate.yml.
  10. Merge queue. Mergify tests the PRs as they will land (batches of 2, 4 at once, by scope); near-proven and main fixes first; a failed batch is split. Lives: .mergify.yml. Source: Mergify docs (C19), merge queues.
  11. Main. The demo updates itself; qa tests the merged app hourly; the nightly runs everything with no retries. Lives: demo-update.yml, nightly.yml, qa skill.
  12. Built, then Proven. The Lead marks the register row. By hand: tonight 4 merged rows are still unmarked.

What we are missing

  • Lanes that wake themselves. Today a lane moves only when someone types to it. A PR comment, a red check or a merge on main should wake the lane that owns the PR (an event trigger or a scheduled routine per lane). Cost last night: about 7 h on A5 and 5 h on A1.
  • Lanes that start without the founder. New lanes start only in a founder-typed turn, so 03:30–07:15 nothing could start. Either a standing queue of pre-started lanes or a scheduled starter.
  • The register updates itself on merge. A workflow that marks a row Built when a PR naming it merges. Evidence: 4 merged rows unmarked at 07:2x; the Lead's records lag cost hours of wrong status.
  • A cap on open PRs. 76 open, 26 drafts, oldest from 18 Nov, 9 Dependabot (#3980–#3986 are major jumps: TypeScript 7, @types/node 26, Anthropic SDK 1.x). A work-in-progress limit and a Dependabot rule that holds major versions for a named review would stop the pile.
  • State, not phrases. "Lead allows round N" is matched as text; a missing phrase cost 5 h. A label or a check status is harder to miss.
  • A nightly on a clock. P-854's three runs a day are dispatched by hand; none since 01:56.
  • A second approver identity. Every PR is authored by the founder's account, so a GitHub approval rule cannot be met (register risk 1). The switch needs a machine user or Approvals connected, and a second org owner (LR-063).
  • CODEOWNERS and a read ruleset. No CODEOWNERS file on main; plan #97 says a ruleset was done on 17 Nov, v3 says "Do now". Read the ruleset before the switch.
  • Records that fit. STATE hit 12 KB twice in one night. A7 (records to the private repository) and a generated status line would end the trims.
  • Less machinery. 51,298 lines of pipeline against 163,826 of product (31%). C15 says strip parts no longer load-bearing; no row today deletes anything. A2 is the first chance.
  • Measures that survive a session. lab-progress.py keeps its rate log in a temporary folder, so each new Lead starts at "not yet measured" or "0.0 rows/h". The DORA baseline (A6) is not committed.
