## Part 1 (CS-D5-1): the preview link and its bytes (expected ~350 lines)
* `POST /api/runtime/documents/:id/preview-link` → `{ url, expires_at, media_type, file_name, size_bytes, uploaded_at, scan: "CLEAN", contains_scripts }`: the document is reached exactly as `file()` reaches it (`"officer"`, 404 in the same words for an unknown id or another firm); a file whose scan state is not `CLEAN` answers 409 "Checking for viruses…" or 410 "Removed — infected file" (AG-9-55's words, the same in the panel; concept m2) and no link is made. The link is the platform's signed token for (firm, the session's staff id, the document's storage key), 300 s (AG-09 line 426: "today 300s"; concept m3), and **single use**: the first successful GET consumes it (an in-process set keyed by the token's MAC until its expiry is enough in the reference app), and a second GET answers 404 like an expired one (concept M2, so no read goes unrecorded); the URL path holds only the token, never a firm's or a person's name. This token route is the local adapter's stand-in for storage signing (AG-09 line 426 "the API never proxies bytes"): the life, the nameless URL, the firm scope and single use carry over; the binding to one staff member does not.
* `GET /api/runtime/document-previews/:token`: the token checked for the session's firm and person (another firm's or person's, altered or expired → 404, leaking nothing), the bytes through `FilesPort.get` with the sha256 recomputed (409 on a mismatch, as `bytesOf`), served with exactly the download's four headers. **The audit line is written when the link is made** (the opening of a preview): one line **"previewed"**, entity `case document`, key the document id, with the person, through the same audit call the download uses (`Audit.log` today, `AuditPort` once AUD-1m lands; CS-D6 lists it). The viewer fetches the bytes once into memory (PDF.js gets an `ArrayBuffer`), so page turns and zoom write nothing more; a second fetch of the same link is refused (single use).
* A small public method on `CaseDocuments` that reaches a document without writing "viewed" (the one export this part adds to `case-documents.ts`); the routes and their service live in new `api/src/features/case-documents-preview.ts` and new `api/src/documents/preview.ts`.

## Part 2 (CS-D5-2): the viewer (expected ~550 lines)
* New `web/src/runtime/document-preview.tsx`: PDFs drawn by `pdfjs-dist` to a canvas from the link's bytes (`isEvalSupported: false`, no scripting); PNG and JPEG fetched from the link with the session's header (`x-actor` today, the staff bearer token on PF-4 routes) into a `Blob` and shown in `<img src={URL.createObjectURL(blob)}>`, revoked on close (an `<img src>` cannot send the header); PDF.js gets the same bytes as an `ArrayBuffer` from that fetch, never a URL; next and previous page, zoom (fit width, 100%, 200%), rotate (view only: nothing saved), and the file's name, size, upload date, "Checked: clean", and "Contains scripts: opened only in the safe viewer" when flagged. Only a clean current file gets the Preview button on its line (a checking one shows "Checking for viruses…", a removed one "Removed — infected file", no button); the panel shows the same words if the state changed after the list was drawn, with no link. The bytes are fetched once; only when that one fetch finds the link expired does the viewer ask for one new link, once; a second refusal shows "The file could not be opened…" (no renewal on page turns: concept M1).
