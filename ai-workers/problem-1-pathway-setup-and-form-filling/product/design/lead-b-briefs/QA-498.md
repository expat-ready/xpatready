**Root cause first (P-502: evidence, root cause, a named framework, no hit-and-trial).** Before any fix, show which of these it is, with evidence in the PR:
1. **The check itself.** `getByRole('heading', …).count() === 1` is read once, at once, with no wait. If the list page renders its heading after the toast (slower under a busier shard), the check is a race. Compare the C6.13 / QA-420 focus check (`run-suites.sh` comments): the same pattern. The standard fix is Playwright's web-first assertion: `await expect(locator).toHaveCount(1)`, or `locator.waitFor()` with the suite's timeout.
2. **The product.** The page lands on `/`, but shows something other than Immigration programs. For example, another suite's state is left in the shared demo database, the router lands before the list loads, or an error state shows. That breaks EXPERIENCE ("a double click does one thing"), so the fix is in the product, and the test stays strict.
3. **Shard order.** The suite reads state another suite left behind. The fix makes the suite set up what it needs, never relying on order.
