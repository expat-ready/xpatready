**What to build:**
* **Part 1, the port (no schema):** new **`ports/legal-hold.ts`** (zod only), in **the shape CS-X3's door asks for** (`design/briefs/CS-X3.md` in open #1876, its contract gap; AUD-5's `check(tx, …)` calls it inside the same transaction): `LegalHoldPort.isHeld(tx, firmId, subjects[]) → Promise<{ held: false } | { held: true; holds: { holdId; scope; reason; placedAt }[] }>`, inside the caller's transaction, **every matching hold reported**, not just the first. A subject is one of `{ kind: "FIRM" } | { kind: "CASE", id } | { kind: "PERSON", id } | { kind: "CATEGORY", category } | { kind: "DATE", at }` (§3.5's scopes plus SA-11-40's person). **Matching:** a FIRM hold matches every subject of that firm; a CASE or PERSON hold matches that id; a CATEGORY hold matches that category; a DATE_RANGE hold matches a `DATE` subject inside its range (§3.5: "a deletion that intersects the hold is suspended"). **Categories:** a typed list `LEGAL_HOLD_CATEGORY` in the port file that ships with CS-X3's five case-side names (`case_documents`, `case_answers`, `case_notes`, `case_tasks`, `case_files`); other modules add their own lines (never rename). **No race:** placement takes `pg_advisory_xact_lock(hashtext('legal-hold:' || firmId))` (exclusive), and the real `isHeld` **takes `pg_advisory_xact_lock_shared` itself** through its `tx` before reading, so no caller (CS-X3, AUD-5, PF-21d, PF-F2, PF-11) can skip it; the port file states this rule. The fake (`fakeLegalHolds()`, with `place`/`release`) and a shared contract `ports/contracts/legal-hold-port.contract.ts`. The firm passed is always the caller's session firm, never a request value. This part can merge first so CS-X3 and AUD-5 build against it.
