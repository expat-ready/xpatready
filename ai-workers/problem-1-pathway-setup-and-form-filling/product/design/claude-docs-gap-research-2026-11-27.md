## Five findings that change planned work (read these first)

1. **The planned Approvals rule for risky paths cannot work in our repository.** LR-070 says risky paths "need a non-author approval". Every PR is opened by the founder's account (register risk 1). A seat written `from: [humans, "!pr/authors"]` excludes the pull request's authors, and the account cloud sessions commit as "doesn't" count as a person (approvals-policy, People lists). That leaves no human who can fill the seat, so once enforced, every risky PR waits forever. P-849 already says the right thing: risky paths need a Code Review pass. LR-070's Done-when must be rewritten to match before `approvals.yml` is written.
2. **Naming Code Review in the policy bills on every push, whatever our Manual setting says.** The ship guide puts it plainly: a policy using Claude's review "can bill whenever you push, regardless of your Code Review settings". The doc example puts `advisory: [claude/code_review]` on `"**"`. Copying it would undo LR-067 (Manual on risky PRs only) and bring back LR-076, which we dropped (Code Review on every push).
3. **"Opus everywhere" is not true in the harness today.** `/goal`'s evaluator uses "your configured small fast model" (the Haiku alias), the built-in `web-fetch` and `claude-code-guide` subagents run on Haiku, and the auto-mode classifier defaults to "Claude Sonnet 5". Our `agent-model-guard.sh` only sees the Agent tool. An org `availableModels` list is the documented way to make this hold everywhere (row 1).
4. **/ship, /steward and Projects do not fit our lanes.** Cloud sessions don't have /ship ("Cloud sessions don't have them"). Our PreToolUse Bash hooks stop the watch from starting in the Lead's copy. In a public repository /ship "doesn't commit anything for you". Project threads skip `.claude/settings.json` hooks and permission rules, so our guards would not run in them.
5. **The approvals guidance assumes GitHub's merge queue, and we use Mergify.** The docs describe how Approvals stamps a GitHub merge queue's commits. Nothing covers Mergify's batch PRs, so the observe week must check them (row 9).
