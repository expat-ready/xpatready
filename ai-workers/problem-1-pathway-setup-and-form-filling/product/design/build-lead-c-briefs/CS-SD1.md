**What is true on `main` (checked by Build Lead C against d66bcfd2d):**
* **The four ids.** `fact_source`, `form_edition_accept`, `person_role` and `validated_copy` are created by their migrations with `"id" UUID NOT NULL DEFAULT gen_random_uuid()` (`20261029090000_w115_fact_sources`, `20261030090000_w110_channels` (two tables) and `20261027160000_s5_person_roles`). Their models say `@id @default(uuid()) @db.Uuid`, which is a client-side default, so Prisma wants to drop the database default. **The database default is needed**: two migrations insert rows without an id (`s5_person_roles` line 23 into `person_role`; `w110_channels` line 35 into `form_edition_accept`), and any later SQL insert would too. So the fix is in the schema: `@default(dbgenerated("gen_random_uuid()"))` on those four `id` fields (models `FactSource` and `PersonRole` in `pathways.prisma`, `FormEditionAccept` in `forms.prisma`, `ValidatedCopy` in `answers.prisma`). Prisma Client still leaves the id to the database, and the id type and values do not change.
* **`canonical_field_name`: keep the table.** Dropping it would be wrong, not safe. It is live: `20261025100000_field_name_unique` made it the database's guard for "one shared-field name per group in a workspace". It has a trigger `canonical_field_name_reserve` on `canonical_field` and the partial unique index `canonical_field_name_unique ... WHERE name_key <> ''`. `api/src/rename-door.ts` lines 79 and 149 turn its 23505 into the 409 "already exists", and `rule-facts.ts` line 243 relies on it (MA1). It is missing only from `library.prisma`. Fix: add model `CanonicalFieldName` to `library.prisma`, mapped to `canonical_field_name`, with the four columns as created (`workspace_id` Uuid, `canonical_field_key`, `group_key`, `name_key` text, all required, `@@id([workspaceId, canonicalFieldKey])`), and **`@@ignore`**. The model is for migrations only, never the client, so the app writes it only through the trigger.
  * **The partial unique index:** if Prisma 7.8 can state it (a `where` on `@@unique`, preview `partialIndexes`, if this version has it and the STANDARDS §1 gate allows the flag), state it. If not, the diff will propose `DROP INDEX "canonical_field_name_unique"`. Then stop and ask in a PR comment, **"Question for the tech lead"**, with the diff lines. **Never drop the index or the table.**
