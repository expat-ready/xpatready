**The defect (QA-397):** an IRCC account the author changes on the Forms tab (APR Portal → PR Portal) reaches every **open** case while still a draft. The case reads "Filed through PR Portal", the Record the submission dialog says the same, a submission recorded meanwhile stores `filing_record.portal = PR_PORTAL` for good, and IRCC's accepted channels on the case are checked against the live account. **Cause:** `api/src/case-prepare.ts` reads the live `combination.portalKey` (lines 160, 177, 417, 718 and 895 on `main`; the row named 159, 674, 851 before later edits). It should read the case's pinned release: `snapshot.combination.portal`. `engine/snapshot.ts` already writes that value, and `api/src/workspace.ts` lines 75 and 113 already read it.

**The fix:** every read of the IRCC account for an open case goes through the case's pinned release (`pin.release.snapshot.combination.portal`, the same pin `case-prepare.ts` already loads for `release_version`). That covers:
* the prepare view's `portal` and `portal_words`;
* `channelOf`'s account at line 417;
* the record-submission path at line 895, so a new `filing_record.portal` stores the released account.

Keep `combinationKey` reads as they are. Find the reads with `git grep -n "portalKey" api/src`. Any other case-side reader of the live account is in scope **only if** QA-397's check touches it; otherwise list it in the PR as a follow-up question. **A submission already recorded keeps what it stored** (never rewritten).
