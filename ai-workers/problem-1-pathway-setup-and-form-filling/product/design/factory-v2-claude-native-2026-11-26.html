How safe is it?

Seven locks, all set by you or by GitHub, not by our scripts

1 · Main is lockedA GitHub branch rule: no direct pushes, the ci check must pass, and a new push wipes old approvals.
2 · Claude can't mergePR Steward is built never to approve or merge. Anthropic's service refuses it. Only GitHub's queue merges.
3 · Risky files need the LeadThe approvals policy keeps the Lead's read for money, schema, migrations and workflow files.
4 · CI stays the gateClaude Approvals can't read CI results, so ci stays its own required check.
5 · Spend has a ceilingA monthly cap on the organisation, on PR Steward and on Code Review. PR Steward has no limit until we set one, so we set it first.
6 · Our guards still runThe push guard and GitHub's secret blocking run in CI, because the watch skips local git hooks.
7 · Easy way backMergify and the old scripts stay in git history. If the first 48 hours go badly, the old flow returns in about an hour.
How we get more power
  • No more account switches. Builders, checks and agents keep running past the weekly limit, up to your cap. Today all of them die every few days.
  • An agent on every pull request, all the time. Fixing a red check no longer waits for the Lead's next check. Today 81–85% of a pull request's life is waiting.
  • The Lead does Lead work. Shaping rows, reading risky changes, proof. No more labelling, relabelling and chasing.
  • Less to break. About 11,000 fewer lines of process code to keep working. The guards that removed labels caused the jams of 5 and 7 Nov.
  • Future-proof. As Anthropic improves these agents, we get the improvements for free instead of rebuilding them.
The switch-over

About two days, product building continues

  1. Sign up for Claude Team and set the caps

    You, ~20 min (payment and admin clicks are yours)

    A small Team organisation (2 standard seats), used only to switch on the agents. Builders stay on your Ultra accounts. Set a monthly cap on agent spend. Install the Claude GitHub App on xpatready. Turn on Code Review, PR Steward (with a cap) and Approvals in watch-only mode. I'll give you each link and the exact button.

  2. Empty the current queue

    Lead, ~2–3 h

    Let the green product pull requests merge through Mergify as they do now. Builders keep building; nothing new joins the old queue.

  3. One switch, then GitHub's queue goes live

    Lead, ~half a day

    Set up the branch rule and merge queue on main, add the approvals policy and our review checklist for Code Review, and switch off Mergify and the label scripts, all in the same switch. This is a tooling change, merged first.

  4. Delete what is replaced

    Lead + 2 builders, ~1 day

    Remove the guard tests, the board, flaky quarantine, the fallbacks and the watch scripts. Cut the lead, lead-watch and next skills and RULES down to one page each of what is ours.

  5. Product merging resumes, measured

    Everyone, first 48 h

    Compare against the last week: time from approval to merge, failed merges, Lead clicks per day, spend. If it is worse, we roll back (lock 7).

Cost, and what I don't know yet

Your worry, answered (26 Nov 15:1x IST): don't move the builders to Team. Per dollar, a Team premium seat gives less usage than Ultra ("5x" a standard seat, at $125 a month, against Ultra's $200). But Claude's agents aren't paid from seat usage. They are billed by use from organisation credits. So the best mix is a small Team organisation (2 standard seats, about $50 a month) only to switch the agents on, with builders staying on Ultra. Account switching for builders then hurts much less, because the agents keep fixing their pull requests after a switch. To stop switching entirely, turn on Ultra usage credits with a cap.

Known (claude.com/pricing, today): Team premium seat $125 a month ($100 if paid yearly), so two seats are about $250 a month. Code Review, PR Steward and extra usage are billed by use against organisation credits, with no flat price published.

Unknown: what 12 builders cost past the seat allowance. I recommend a first-week cap (you pick the number), then I report the real daily spend so we can size it. Team has no "Projects" feature yet; we don't use it today. Your Ultra accounts can stay active as a fallback during the first week.

Cheaper alternative: keep one Ultra account with usage credits and a cap. That also ends switching, but without Code Review, PR Steward or Approvals.
