**M1 | Major | api/src/front-office/signing/service.ts:197-228 (signed/viewed branch, `moveRetainer` result ignored); api/src/front-office/retainers/service.ts `withdraw`, `signedOffline`, `edit`**
- Wrong behaviour: withdrawing, editing or signing a retainer on paper never ends its signing request or envelope. The webhook checks only the request's status, so it still records signatures on a dead agreement.
- Input → result:
  - Send, Withdraw, then the client's `signed` event. The request is still SENT, so signedAt is written, the request goes to CLIENT_SIGNED and the audit says "Signed by the client". `moveRetainer` matches 0 rows and nobody checks. The answer is `applied: true`. The retainer is WITHDRAWN, while GET /retainers/:id/signing says "CLIENT_SIGNED, 1 of 2 signed".
  - Edit to v2 (DRAFT) works the same way: v1 takes the client's signature, and the next Send silently cancels that client-signed request as UPDATED.
  - After `completed` on a withdrawn retainer, the request stays CLIENT_SIGNED (live) for ever.
- Clause: "on `retainer.withdrawn` … the request is cancelled at the adapter and the client gets 'Agreement withdrawn'"; checklist 2, 5. The cancel reasons WITHDRAWN and SIGNED_OFFLINE are never written.
- Confidence 85. Signature acceptance is IN this change. The missing cancel on withdraw, paper signing and edit is left unaddressed beside it.
