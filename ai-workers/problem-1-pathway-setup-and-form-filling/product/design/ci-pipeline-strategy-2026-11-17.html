Why quality does not drop

  • Every merge still passes every suite and every Works pack on the combined code before it lands. That is where the real catches happen: 73% of failed batches were two PRs clashing, which a PR check cannot see.
  • The PR check keeps the same suites. It runs once on the approved head instead of on every push.
  • One gate is added: the container proof in the batch (closes QA-449, unblocks R1.16).
  • Not proposed: running no suites on the PR. 62 of 193 code PRs (32%) went red on their own PR check. Without that check, nearly 9 batches in 10 would hold a broken PR. Quality would hold, but merging would nearly stop.
  • Not proposed: the cheaper "direct" PR selection. It runs 27% of the suite time, but in a replay 5 of 20 red PR checks would have gone green and broken in the queue instead.

Delivery: why nothing was proven overnight

101 Release 1 rows: 11 Proven, 26 Partial, 64 Not built (qa/CAPABILITIES.md, 07:5x IST). The 21 overnight merges were mostly first or middle parts. A row counts only when every part is on main and qa proves it.

Nearest to Proven, each waiting in the CI line now: R1.4 walls audit (#2029) · R1.49 consent gate (#1956, #1961) · R1.80 forms per applicant (#2013, then QA-165) · R1.37 booking page (#1918) · R1.16 automated testing (one CI change: the container proof in the batch).

Order: unjam those first → then whole journey groups, one group per lane: Messages → Sign-up → Permissions → Booking → Leads → Retainer and money → Platform records → case-side gaps. No new capability while a started one waits (P-606).

Lane cap: one merged code PR uses about 1,280 machine-minutes. 40 machines carry about 36 code PRs a day (about 10-12 code lanes); Team about 54 (about 15 lanes); Team plus one-check-per-PR about 65 (about 18-20 lanes). When batch waits pass 15 minutes, lanes do review fixes, qa bugs or design, not new PRs.

Ultracode, in plain words

A Claude Code setting (/effort ultracode; settings key ultracode) that lets Claude split a big task into a script of many helper agents running at once. The official docs say a run "can use meaningfully more tokens" (code.claude.com/docs/en/workflows.md, read 17 Nov 2026). Our limits are CI machines, qa proof and the weekly plan, not how fast code is written. So it stays off for builders, and is used only by the Lead for wide read-only work, such as re-reading many rows' evidence.
