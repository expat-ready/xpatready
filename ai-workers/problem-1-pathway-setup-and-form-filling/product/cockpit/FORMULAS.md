# Board formulas (P-596; spec `cockpit/spec-a61-a62-2026-11-14.md` draft 3)

Every number the board shows for spec §1-§5 and §7, with its formula, source, provenance class, threshold and owner. `tools/cockpit-data.py` computes them **from the frozen snapshot only** (§6 1a); `tools/test_cockpit_data.py` checks each one against hand-worked numbers on `tools/fixtures/cockpit/snapshot/`. A fresh reviewer audits this sheet against the sources before each version is published, and weekly (P-591).

**Provenance class** (§0.3): *measured* = GitHub or git; *parsed* = a hand-kept record file at the records sha; *reported* = Lead input (shown "Lead-reported"). A number built from measured and parsed inputs is marked *parsed* (the weaker class) with sha `records <sha> + main <sha>`. Every number carries `src`, `sha`, `as_of`, `class`; a null carries `reason` and the page shows **not measured** (schema `cockpit/data.schema.json`).
**Words (§11 R9)**: one word per state on the strip, Overview and heat map: **built** (all parts merged) and **proven** (qa Works); "verified" is not used. Where the checklist's hand-kept status and the computed state differ, the row shows both with a "records differ" mark, and Details › Data trust lists them with the invariant results. Labels are plain words ("rows ready", "older than usual", "open app changes"); code keys never reach the page.
**Owner** of every number, its formula and its source data: the current Lead (STATE `current_lead:`), unless a row says otherwise. **Times:** "IST day" = the timestamp in UTC+05:30, then its date; "today" = the IST day of the snapshot's `taken_at`. Anything merged after `taken_at` is ignored.

## Snapshot (§6 1a) and what each script reads
`<out folder>/snapshot/`: `meta.json` (`taken_at`, `repo`, `main_sha`, `records_branch`, `records_sha`; plus `extra`: records lag by git, read only by this script) · `github/pulls.json` (every PR, state all; `files_app` = `tools/app-code-prs.sh`'s rule, classified for open PRs, PRs merged in the last 21 days and every PR whose title starts with a row id; other PRs `null`) · `github/main_checks.json` · `github/guard_runs.json` · `github/branches_recent.json` (every branch read; kept when its head commit is under 24 h old; GitHub keeps no push time per branch, so the head commit's committed date stands in) · `files/<repo path>/` (MVP-CHECKLIST.md, BACKLOG.md, STATE.md, cockpit/plan.json, cockpit/history.jsonl, qa/BUGS.md, cockpit/health-exceptions.json, cockpit/usage-log.tsv at `records_sha`, by `git show`) · `git/checklist_records.jsonl` + `git/checklist_records/<sha>.md` (MVP-CHECKLIST.md commits on the records sha: the 48 h before `taken_at` and the one before them; §1b) · `files_main/qa/CAPABILITIES.md` (at `main_sha`) · `git/capabilities_main.jsonl` + `git/capabilities_main/<sha>.md` (main commits touching it, 30 days) · `git/bug_first_seen.json` · `briefs.json` · `lead-input.json`.
**Extra files** (this script only; not part of the shared layout): `github/main_nightly.json` (newest finished nightly on main), `github/open_prs_detail.json` (each open PR's head commit time, CI rollup, and when `review: approved` went on). Since board v53: `github/issue_comments_today.json` (every issue and PR comment updated since 00:00 IST of the snapshot's day: id, PR number, `created_at`, whether its author is a bot account, the body's first 60 characters; no login is kept) and `github/ci_failed_runs_today.json` (ci.yml runs created since 00:00 IST whose latest attempt failed, with each failed step's job and step name); both are read by `tools/cockpit-reconcile.py` too. A file is absent when its read failed, and its number is then not measured. **REST fallback** (cloud sessions refuse GitHub GraphQL): `branches_recent.json` then comes from the repository's push activity of the last day (`/activity`: push, force push and branch creation, a branch's first push; the newest per branch that still exists), whose time is the push itself rather than the head commit's committed date; `open_prs_detail.json` from each open PR's head commit, check runs and statuses (CI state: any failed run or failed status → failure, any unfinished → pending, else success; none at all → none) and its `labeled` events. The run notes say when the fallback was used.

## Shared definitions
* **Row id** (BACKLOG row): a token shaped `[A-Z][A-Za-z0-9]*-[0-9A-Za-z]+(-…)*` (PF-4b, BK-17, B5-filings, DB-SPLIT, PF-L), not a decision (`P-n`) or bug (`QA-n`) id; it never matches inside a longer id ("PF-4" is not in "PF-4b"). "BK-22 to BK-24" expands to three ids.
* **Build rows**: the table rows of MVP-CHECKLIST.md section "## A." under a "### X." group (A to L) whose first cell is a map number; columns found by header name. **Parts** of a row = the row ids in its "BACKLOG rows" cell. **Shaped** = Status does not read "Not shaped". **Unshaped or unnamed part**: the cell says "none yet", or a part sits in a ";"-segment that says "named only".
* **Title match (§11 R1)**: the id appears anywhere in the title as a whole token: not preceded by a letter, digit or "-", not followed by a letter or digit ("PF-4" never matches "PF-4t"; "BK-1" never matches "BK-18"). **Records PRs** (title contains "(records only)", or the `records` label) and merge-queue PRs (`mergify/` branches) never count.
* **Merge date of an id (N2, R1, R1b)** = IST day of the earliest `merged_at` among merged non-records **app-code** PRs (`files_app` true) whose title matches it. Changes, built and scope use this; ready rows use any non-records merged PR (R1b). Accepted limit (R1b): a title that only mentions an id (e.g. "screens: C7.6 — BK-18 (QA-448)") still matches.
* **Release 1 changes (N2, §11 R5, R5b)** = distinct ids cited in the Build rows' cells, exactly; a BK- row counts only when the checklist cites it (today BK-10, BK-14, BK-16, BK-17, BK-22, BK-23, BK-24 in map rows 77, 80, 99).
* **Cited ids not in BACKLOG (§11 R4)**: in a row whose Status is not "Shaped" such an id is an unshaped part (the row is not built); in a "Shaped" row it is an invariant failure.

## §1b Delivery per use (P-602 (4), 14 Nov; review fixes the same night)
**Window**: the 24 h ending at the snapshot's `taken_at`; a time t is inside when `taken_at − 24 h < t ≤ taken_at`. **Span**: from the first to the last reading that the plan % uses (below), `(first, last]`; the deliveries divided by the plan % are counted over the span only, so both sides cover the same hours. With no usable readings the span is the whole window. The page says "last N h of readings". Shown on Overview under the pace line, with "not measured" said once per line.
**qa Works at a time t (one rule for "done" and "needed", the qa queue's rule, §2)**: the row's checklist Status reads "qa Works" (emphasis and `\*` removed, cut at " (" or ";") in the checklist as it stood at t (at `taken_at`: the snapshot's checklist; earlier: the newest records commit of MVP-CHECKLIST.md at or before t, from `git/checklist_records.jsonl`, which holds every commit in the 48 h before `taken_at` plus the one before them), **or** the row is proven by t (once the checklist has a qa id column; proven time = the commit time of its first all-Works commit, as for Proven). When the snapshot's checklist history does not reach back to t, the count is not measured.
| Number | Formula | Source | Class | Threshold |
