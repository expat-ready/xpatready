## Important

**I1. Flag warnings and translation items are dropped for a file that is a substitute-set member. Bug class: wrong join key, set member vs line key.**
- **Where:** `prototype/studio/api/src/case-document-flags.ts:182-189` (`flagWarningsOf`), used at `prototype/studio/api/src/case-prepare.ts:287` and `:292`.
- **What goes wrong:** `flagWarningsOf` keys each warning by `${d.subjectId}|${d.documentType}`, where `documentType` is the stored file's type. On a C6.15 line with a substitute set, the upload stores the file under the member's key (`case-checklist.ts` upload: `documentType: member.key`). That key is not the line's key. Readiness looks the warnings up by the document item's `document_type` (`case-prepare.ts:512`: `w?.document_type`, the checklist line's key). So an expired, too-old or untranslated file that is a set member never reaches readiness.
- **Why it matters:** the checklist shows the same warning on the line, because `docsOf` takes the line's set keys. The two views disagree, and the claim "readiness reads each current file's flag warnings" is not true for set lines.
- **Same cause in the not-applicable filter:**
  - `flagWarningsOf`'s `off` set (`case-document-flags.ts:182`) is keyed by the line's `documentType`, so it never matches a member file.
  - The checklist's translation filter has the same problem (`case-checklist.ts:220-222`, `off.has(x.documentType)` with `off` built from `rows[].documentType`). A Not applicable or Waived set line still shows a "Translation + translator's affidavit" line for its member file, which break m3 meant to stop.
- **Fix:** resolve each file to its checklist line through `caseDocument.checklistLineId`, or through the line's set keys, and then:
  - key `flagWarningsOf`'s map by that line's `documentType`;
  - test Not applicable / Waived against that line in both `off` filters.
- **Test to add first:** in `check_csd5_flags.ts`, on a set line, upload a member file whose key is not the line's key and give it a past expiry. The test fails today because no `document_flag` warn appears in `/prepare`. Then mark the line Not applicable and check that no translation line is shown.

## Nit

**N1. A missing expiry date becomes a readiness item to pass, which the PR does not claim. Bug class: scope beyond claim.**
- **Where:** `case-document-flags.ts:139` (the `no_expiry` warning) flows through `flagWarningsOf` into readiness.
- **What happens:** every current file on a `has_expiry` type with no date entered becomes a `document_flag` warn on every filing, and each one must be passed with a reason. R1.70 (`qa/built/R1.70.md`) and `CODE_WORDS.document_flag` ("expiry, age or translation") name only expired, too old and translation needed.
- **Fix:** either keep `no_expiry` as a checklist-only hint (filter it out in `flagWarningsOf`), or name it in R1.70 and `CODE_WORDS`.

**N2. The readiness translation item has no passing test. Bug class: test proves nothing.**
- **Where:** `tests/check_csd5_flags.ts`. The "pass (4)" test asserts only the Expired item. The "fail (4)" test asserts only that there is no translation item once the translation is Provided.
- **Fix:** add one assertion that a Required translation (passport in Spanish, translation not Provided) gives a `document_flag` warn matching `/Translation \+ translator's affidavit needed/` in `/prepare`.
