# Review: PR #3716 (FO-9s part 3, the guided merge dialog), round 1, full review

1 Important, 3 Nit, 0 Pre-existing

Scope: web only (merge-dialog.tsx, people-to-merge-page.tsx, review-contract.ts) plus tests. It touches no money, permission, sign-in, schema, migration or CI code, so it is not a risky PR under §5. The server keeps every refusal (STALE_VERSION, HAS_MONEY, NEEDS_CASE_SIDE). I checked the stale-version path, the money and case gating, the payload (survivorId, every field's pick, updatedAt), the lost-answer and 5xx wording, and the Undo wiring on the notice against the code and the G1-G8 checks. All of them hold up. The global `refetchOnWindowFocus: false` (web/src/lib/api.ts:46) means a window focus does not quietly refresh the preview's `updatedAt`.

## Findings

1. **Important**: keyboard focus is lost when you change which record stays. Bug class: "focus lost on refetch".
   `web/src/modules/front-office/duplicates/merge-dialog.tsx:34-38, 80, 85-88`. The preview query is keyed on `survivor`, with `gcTime: 0` and no placeholder data. When you change the "Which record stays" radio, the new key has no data, so `preview.isPending` is true. Line 80 then swaps the whole body, including the radiogroup you are on, for `<Loading>`. The focused radio is unmounted. Focus falls to the dialog container (or the body), and a second arrow key does nothing. A keyboard or screen-reader user loses their place on every switch, which breaks WCAG 2.4.3. The build notes promise better focus handling and the dialog claims "keyboard only". G7 (`tests/check_fo9s_merge_browser.ts:219-221`) does not prove that claim: it presses ArrowRight once, checks only `isChecked()`, and never checks `document.activeElement` after the reload.
   Fix: keep the survivor radiogroup mounted while the preview loads. Either render it outside the `preview.isPending` branch and show `<Loading>` for the field table only, or use `placeholderData: keepPreviousData` and mark the table busy. Then add a G7 check: after ArrowRight and the reload, `document.activeElement` is still the survivor radio, and a second arrow key moves it back.

2. **Nit**: Back then Next turns "Merge 2 people" back on after a final refusal. Bug class: "state reset re-enables action".
   `merge-dialog.tsx:32` (`go` calls `setError(null)`) together with line 69. After a 409 that cannot succeed again (HAS_MONEY, KEPT_SEPARATE, MERGED_AWAY, NOT_LISTED), or after STALE_VERSION, Back then Next clears `error`. The button comes back on against the same old preview, even though the header (line 10) says such a refusal "turns Merge 2 people off". The server refuses again, so the risk is low. G6 checks the button only straight after the refusal.
   Fix: keep the `final` and `stale` flags when the step changes. Clear only the message, or clear them only on Reload or a new preview.

3. **Nit**: the notice's Undo stays enabled after a refusal, and focus goes to an element that may not be there. Bug class: "stale action after refusal".
   `people-to-merge-page.tsx:146, 150`. When Undo on the notice is refused, the warning shows (line 150), but the button's `disabled` checks only `undoneAt`, so you can press it again and get the same refusal. The undo `onError` and `onSuccess` also send focus to `[data-dup-merge=…] [data-dup-after]`, which is not rendered while To review is the active tab.
   Fix: disable or hide the notice's Undo when `refused[done.mergeRef]` is set. Send focus to the notice's warning, or to the notice itself, when the undo started from the notice.

4. **Nit**: `fieldWhy`'s "present" test differs from the server's rule. Bug class: "client/server rule drift".
   `review-contract.ts:45`. The client treats `" "` (blank text) and `[]` (an empty list) as values. The server's `defaultPick` (`ports/person-merge.ts`, `present`) counts trimmed-empty strings and empty arrays as missing. For such a value the "Why" column can say "newer" or "same" when the server chose by "only value".
   Fix: mirror the server's `present` (trim strings, treat empty arrays as missing), or have the preview return the reason for each default.
