PF-F4 (runtime, an enabler; map row 67): every upload door now has one check to call, `api/src/platform/files/file-type.ts`. The file's type comes from its own bytes (PDF, JPEG, PNG, HEIC, TIFF, Word, Excel); an `.exe` renamed `.pdf`, HTML, SVG, old `.doc`, `.docm`/`.xlsm` and a plain ZIP ("Upload the files inside one by one") are refused; Word and Excel are recognised from the ZIP's directory without decompressing anything (a 2 GB declared entry is read in well under 50 ms). Size limits are 25 MB for documents and 10 MB for images, on the declared size when an upload opens (`checkDeclared`) and on the bytes at the end (`checkFile`). A file whose name disagrees with its bytes is stored under the bytes' type with its name corrected (`passport.pdf` that is a JPEG → `passport.jpg`; `cv.docx.exe` → `cv.docx`); an image header over 89.5 megapixels (Sample) is refused; a PDF with `/JavaScript`, `/OpenAction`, `/AA`, `/Launch`, XFA or embedded files is kept and flagged "Contains scripts: opened only in the safe viewer". Each door narrows the kinds; every refusal lists the allowed types in words and ends "Nothing was stored." Nothing on screen changes until PF-F2 and CS-D1 call it; run `tests/check_pff4_file_type.ts` (labels `PF-F4:`, 54/54).
