## The changes, read against the code (underneath)
- **Keep-alive:** 65 s is above the 60 s idle default of common load balancers, so in production the balancer closes first. The comment says honestly that the race is bounded, not removed (a client idle ~65 s on one socket while the server is busy).
- **headersTimeout 66 s** (was Node's 60 s): a slow-headers client now holds a socket 6 s longer. The server listens on 127.0.0.1 only, behind the proxy, so no Release 1 effect. Noted only.
- **Strict mode:** off unless `JOURNEY_STRICT=1`; the GitHub warning for a vitals miss is not printed in strict mode because the miss throws instead. Default output is the same as before.
- The fail half of check_lr110 depends on timing (3 s busy window around the 6 s close). It passed here on the first run; if it ever flakes on a loaded runner, it is the reproduction half, not the fix, that misses.
