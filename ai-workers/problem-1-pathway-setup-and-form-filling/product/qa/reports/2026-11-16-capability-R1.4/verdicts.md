### Rulings
1. **A log line is not the audit line.** This project has one trail, `audit_event`: append-only, kept, and the firm's to read (MODULE.md P-571 (1); R1.88). Server logs are kept 90 days (R1.13), the firm cannot see them, and they hold no actor. So no audit of a bypass exists anywhere, and the brief's Major applies. I agree that one `audit_event` row per staff request's authentication is noise, not a trail. The fix is to take the own-firm doors off the bypass, not to waive the clause. Break 6 also stands: a raw `set role xr_staff_bypass` as `xr_app` writes nothing at all (accepted by design, Minor).
2. **"Named platform jobs" versus the request doors: wording, not a fault.** BACKLOG PF-12 and PF-4s say "named routes" and "named uses". 9 of the 14 uses are doors that resolve their own firm. The Done when should say "named uses (platform jobs and listed doors)". One real point is folded into finding 1: `platform.identity.authenticate` (`^[A-Z]+ /api/`) and `platform.web-address.host` (`^[A-Z]+ /`) list every route, so "refused off its list" is nearly empty for those two.
3. **A refusal proven only in the pack is enough.** `BypassRefused` guards against a programming error (500). That no API call can reach it is the intended outcome, not a missing test. The fail cases run on GitHub's runners in a CI-run suite.
4. **Gate A reaches R1.5's first step.** See above. It is not on GitHub's runners: `tests/qa/` runs in no workflow. The pack carries the API half (P-339).
