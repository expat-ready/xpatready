# P1-pool break report (runtime: WalledPool refuses a pooled connection that is not idle)

Breaker, 24 Nov, Opus 5.5. PR #3428, branch `claude/runtime-pool-rollback` @ a4365b0ac. S = `prototype/studio`. Fix under test: `S/api/src/platform/firm-scope.ts:465-509` (`closeOnOpenTransaction` :475, checkout retry `idle()` :492-499, `query()` override :511).
**Setup:** the real `WalledPool` and Prisma 7.8.0 (`@prisma/adapter-pg` 7.8.0, pg 8.22.0, pg-pool 3.14.0), connecting as **xr_app**, with `wallUnscopedQueries()` called as the API does. One scratch database per attack (`xr_studio_p1brk_*`, all dropped afterwards) with a `note` table under forced RLS (`firm_id = app.firm_id`), seeded `A-secret` and `B-secret`. So "firm data across the wall" here means a real RLS read, not a read-back of the setting. For the red run, origin/main's `firm-scope.ts` (a26e80b6a) was copied to the scratchpad with absolute imports, and the same scripts ran against it (`IMPL=main`). Scripts: scratchpad `h.ts`, `a1.ts` to `a5.ts`. Nothing was added under S/tests. The PR's own test ran green: `npx tsx --tsconfig api/tsconfig.json tests/check_pool_tx_return.ts` gives 11 passed.

## What held

* **Error thrown inside `$transaction` with its insert in flight** (a2.ts 1). The insert is rolled back. B runs as B outside any transaction. Status at release 'I'.
* **Timeout while a single query is in flight**, with a later statement in the callback (a2.ts 2). Nothing is committed. The later call is refused because the transaction is closed.
* **Dropped socket** (a2.ts 3). `pg_terminate_backend` inside a transaction and on an idle client. No write is kept. The next checkouts run as their own firms. Pool and backend counts match (1 and 1).
* **Nested scopes inside a transaction** (a2.ts 4). `withFirm(B)` or `asBypass` inside firm A's transaction, used on the tx client, runs as A. A nested `$transaction` (SAVEPOINT) with a local firm change, then refused, keeps nothing of B, and the next checkouts are right. `withFirm(B)` inside a *bypass-opened* transaction runs as the bypass role, which is the documented rule (firm-scope.ts:54, "a transaction keeps the firm and role of the context that opened it"). Not a P1 finding.
* **Timeout racing the commit**, 60 times (a2.ts 5). The caller is told success exactly when the row is stored (36 ok, 24 timed out). No client is left 'T'.
* **`query()` override** (a1.ts R4, a3.ts 9). BEGIN by promise and by callback, and a failing query, all lead to destroy. B's insert is committed as B.
* **Destroy churn** (a3.ts 8). 300 releases inside a transaction, 10 concurrent waiters, max 3. All 300 served in about 1 s. No deadlock, no wrong firm. Sampled every 2 ms, `pg_stat_activity` peaked at 3 = max, with 0 left after `end`, and `totalCount` matched it. pg-pool drops a removed client from `_clients` before `end()` finishes, so a one-round-trip overlap above max is possible in theory; it was not seen.
* **Checkout guard on a client in a failed transaction ('E')** and a client used after its release: destroyed, and another handed out (the PR's test, re-run).
* **Load-time check** (a5.ts). With `pg.Client.prototype.getTransactionStatus` deleted, importing firm-scope.ts refuses with the P1 message. With a pg that returns `null`, every checkout fails closed (error, 0 connections left), never a wrong firm.
* **No session-state drift from the pool itself.** `set_config` at checkout now only runs on a client proven 'I' (except the m1 race). A later ROLLBACK can no longer undo it behind the tag.

## Verdict reasoning

The P1 Blocker is closed. Every original route (interactive, batch, bypass-opened, raw BEGIN, and 1,200-operation concurrency) is red on main and green on the PR, through RLS as xr_app. Nothing in this PR causes M1. It exists on main, the P1 guard cannot fix it by design (the stray statement is already sent), and it needs a separate mechanism, so it should be its own item rather than a change to this PR. m1 to m4 are hardening.

Verdict: Approve a4365b0ac50c5b1a6f13c99b30fb84d5cc11443f
