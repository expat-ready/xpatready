## Findings (all Minor)
1. **Double submit within one task is not guarded.** `busy` is React state, so two `requestSubmit()` calls in one task both pass `if (busy…)`. Sign-up then sends 2 POSTs, which means 2 emails, and the email that arrives first holds a link that is already dead: confirming it shows "This link has expired or was already used." (seen in this run). The same happens on Confirm: 2 POSTs. If the 200 answer comes back first, the 404 that follows overwrites the "done" view, so the person never sees their firm key. Real double-clicks and a double Enter were held (H7), so this is Minor. `signup-page.tsx:167,178`, `verify-page.tsx:324,326,335`. **Fix:** a `useRef` in-flight flag, set synchronously before the first await, in `send`, `again` and `confirm`. In `confirm`, ignore any answer that arrives after the view is `done`.
2. **Send it again after a terms change is a dead end.** With a DATA_PROCESSING version published after the first send, the check page shows "Not sent / Some answers need changing." (the door's generic detail). There is no field to change and no way back to the terms except "Start again". `signup-page.tsx:198`. **Fix:** in `again`, handle `RELOAD` or an `acceptedTerms` error the same way `send` does: go back to the form (`setSentTo(null)`), re-read the terms, clear the tick and show "The terms have changed…".
3. **A terms url smuggled with a tab leaves the site.** `/\t/evil.example/terms` passes the database check `^(https://|/)` and `safeUrl` (`/^\/(?![/\\])./`). The browser strips the tab, so the Terms of Service link resolves to `http://evil.example/terms` (attribute and resolved `href` read in this run). This needs write access to the insert-only table, hence Minor. `web/src/modules/platform/terms/contract.ts:26`, re-exported at `signup/api.ts:43`, used at `signup-page.tsx:269`. **Fix:** `safeUrl` refuses any control character or backslash (`/[\u0000-\u001F\\]/`), or resolves `new URL(url, location.origin)` and accepts only the same origin or `https:`. Tighten the database check to match (the terms module's change).
4. **Focus is lost to `<body>`** after Change, Done (plan picker) and "Wrong email? Start again": the focused button unmounts. A keyboard or screen-reader user starts again from the top. `signup-page.tsx:243,245,210`. **Fix:** move focus to "Choose a plan" on Change, back to Change on Done, and to Work email on Start again.
5. **Server refusals in the summary do not name their field.** The summary list reads "Not only spaces." and "2 to 120 characters." without saying which answer is meant. `signup-page.tsx:215,230`. **Fix:** prefix each summary item with its label ("Password: …", "Firm name: …"), or link each item to its field.
6. **There is no "too many tries" state (concept §7b m5).** After 5 wrong codes, the right code gives "This link has expired or was already used.", which reads as if the person had done something else. `verify-page.tsx:334-335`. **Fix:** count `CODE_WRONG` answers in the page. After the 5th, show "Too many wrong codes. Send a new link." with Send a new link. The door's single 404 is unchanged.
7. **The confirm page claims a code it does not have.** "The 6-digit code from the email is filled in" shows even when the link has no code or a garbled one; `#code=12a3 45` pre-fills "12a3 45" as is. `verify-page.tsx:316,359`. **Fix:** pre-fill only `/^\d{6}$/`; otherwise leave the field empty and say "Type the 6-digit code from the email."
