## Findings

**B1 Blocker: one person's unsaved draft reaches the next person, who can save it under their own name. Cross-firm, record titles and drafts also persist.**
Drafts (`xr.draft.<record>`, `lib/sync/drafts.tsx:16,27-31`) and tabs (`xr.workspace.v1`, `components/workspace.tsx:20,52-60`) are keyed by record only. Nothing clears them at sign-out: `session.ts:40` `endSession` → `setStaffToken(null)` drops only the query cache. That breaks the rule of `session.ts:35`: "A new person (or none) never sees the last person's rows (break S2)".
* Same tab, same firm: user-O opens lead L-00005 → Edit phone → types `+1 416 555 7777` (no Save) → Sign out. Storage still holds `xr.draft.fo-person:4cd9…:phone`. user-T signs in **in the same tab with the in-app form, no reload**. The lead opens with the field already open and showing O's number, and the line "Unsaved changes to the phone number". T presses Save → **200**, `phone=+14165557777`, audited as T. The same happens after a reload.
* Two windows, two people, one browser: staff sessions are per tab (sessionStorage). Window 1 is signed in as O and window 2 as T. O types `+1 416 555 8888`; it appears at once in T's field, with "also open in 2 other windows" (`drafts.tsx:45` writes every broadcast draft, whoever sent it). T can save it.
* Cross-firm: user-S (sample-solo) opens office Brk Halifax, types "Brk Halifax SECRET draft 3" and signs out. user-T (sample-firm) signs in in the same tab. The strip shows **"Office: Brk Halifax"**, the other firm's record name, and its address. `xr.draft.platform-office:3934…` holding the other firm's typed values stays in T's storage. Tabs that are not open never re-render, so the old title stays as long as the tab does. Over BroadcastChannel, a window of firm A also stores firm B's drafts.
* Expected: drafts, tabs and presence are scoped to the signed-in staff member and firm (for example a `firmId:staffId` prefix, and clearing on sign-out or session end), and broadcasts from another person are ignored. Actual: shown above.

**M1 Major: "Keep mine, then Save" silently drops my change when a colleague changed a linked field.**
Repro (my office, NS): I set Province to AB. A colleague moves the office abroad (`country GB`, 200). I press Save → 409, and the conflict table shows "Where: Saved now United Kingdom / Yours **AB, Canada**". I choose Keep mine: the form now shows **Outside Canada**, and Save is enabled. I press Save → stored `GB|no province`. My AB/Canada is gone and nothing says so. Cause: `mineOnto` (`drafts.tsx:65`, `:130`) carries changes key by key. `inCanada` was not "mine", so it takes the colleague's `false`, and my `province` is kept but hidden. `office-panel.tsx:65` then sends `where` from `inCanada=false`. The fix is to treat "where" (inCanada, province, country) as one unit in the rebase and in the table, or to block Keep mine when the result differs from what the table promised. Breaks §2.13 "Keep mine" and BIC-21 "nothing is overwritten".

**M2 Major: after a reload, a draft in an inactive tab loses its dot and its "ask before close", and the leave-page guard is gone; the 12-tab cap drops a drafted tab silently.**
* Type a name in the Brk Halifax tab, then reload on the Offices list. The office tab shows **no dot**. × closes it with **0 confirm dialogs**. A synthetic `beforeunload` is not prevented, because `anyDraft()` (`drafts.tsx:72`) only sees drafts already read into memory and dirty state comes only from mounted panels (`workspace.tsx:66,98-102`). The draft stays orphaned in sessionStorage, and closing the browser tab loses it with no warning. §2.13 says "a tab with unsaved changes shows a dot and asks before it closes; leaving the page with a draft asks".
* Store 12 tabs, the last one being the drafted office, then open `/front-office/leads` directly. `load()` (`workspace.tsx:58`) `pop()`s the drafted tab with no cap message (12 tabs, `[data-ws-notice]` empty). The draft is orphaned.

**M3 Major: at 1024 px the whole page scrolls sideways once the strip is full.**
At 1024 px with one tab, the document is 1024 px wide. With 12 short titles it is **1145 px**, and with long titles 2533 px. The tab buttons spill past the tablist's own scroller (the widest elements are `button.group … max-w-56 min-w-24 shrink-0`, right edge 1128). The sticky strip wrapper (`workspace.tsx:220`) has no `min-w-0`/overflow clip inside the column flex. BIC-20 / EXPERIENCE §2.12 require 1024 px with no sideways page scroll. At 512 px (1024 at 200 %) the "Open items" menu shows and nothing scrolls sideways, which held.

**m1 Minor: a corrupted `xr.workspace.v1` blanks the app for good in that tab.** `{"tabs":[{"id":"o1","path":"/platform/team","title":{"x":1}}]}` gives React error #31: no strip and no page. It stays blank on every reload, because the render crashes before the effect rewrites storage. Nothing checks the shape (`workspace.tsx:54`, title rendered at `:231`). Related problems: `null` entries render as empty tabs; an id containing `"` throws in `focusTab`'s selector (`:39`) on Alt+PageDown; tabs with `//evil.example/x`, `javascript:…` or `https://evil.example/` throw a `pushState` SecurityError and become dead tabs. Only same-origin script can write this storage.

**m2 Minor: a malformed stored draft's version reaches the user as API wording.** A draft with `version:"\"x"` → Save sends `if-match: ""x"` → the panel shows "Not saved: If-Match: the one version the record was read at, in quotes, as its ETag gave it." Drafts are not shape-checked either (`drafts.tsx:30`). Wrong types give empty fields; no crash.

**m3 Minor: keyboard.** When an arrow key on the strip lands on an office-edit tab, its panel opens and Radix moves focus into the name field. The next arrow or Delete acts on the field, not the strip. While a panel is open, Tab cannot reach the strip because of the modal focus trap. Alt+PageUp/PageDown still work, so a keyboard path exists.

**m4 Minor: PATCH `front-office/people/:id` without a version is last-write-wins.** With a stale version T gets 409 STALE; the same request with no version gets **200**. The design note §3 records this as intended, and the only web caller always sends a version, so it stays Minor.

## What held
* **If-Match:** `W/"…"`, `*`, a list, an unquoted tag and two If-Match headers → 422. A body version that differs from the header → 422. If-Match on an unversioned POST → 422 "does not take a version". If-Match on GET is ignored. The guard runs first: wrong role → 403, no session → 401, before any 422. A header with no body → a no-op 200.
* **Versions and ETags:** a stale version (header or body, including a number) → 409 with `current`. A save's answer has a strong ETag equal to its `version`. Reads carry no version ETag, only Express's body-hash `W/`. Firm profile: revalidating with the same body → 304; after adding an office (offices 12→13, version unchanged) the same If-None-Match → **200** with the new body; `If-None-Match: "<version>"` → 200.
* **People PATCH:** a stale If-Match → 409 STALE with the current phone. Another firm → 404, with or without a version, so it does not reveal whether the person exists. `version:null` → 422.
* **Conflicts:** C1, I change the name while a colleague changes the time zone: Keep mine → stored `name mine, zone Toronto`; the colleague's field is kept and only "Office name" is listed. C2, both change the name: Use the saved version → the field and the DB hold the colleague's value.
* **Hostile storage:** bad JSON and a non-array `tabs` are ignored. 1000 tabs with 5000-character titles → capped at 12 and truncated. No off-origin navigation. `<img src=x onerror=…>` in a draft or a title renders as text (React escaping), and the server receives it as plain text.
