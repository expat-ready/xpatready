## Issues, ranked
**Must**
1. **(b) "Keep mine, then Save" writes back fields I never changed, and so undoes someone else's save.** `lib/sync/drafts.tsx:113` `rebase` keeps the draft's *whole* values on the newer base. `office-panel.tsx:95` then diffs every field against the new base. Probe P1: I changed only the name. A colleague changed the time zone Toronto→Halifax (200). My save → 409, and the table showed a "Time zone" row with "Yours: America/Toronto" (a value I never typed). Keep mine → Save → DB `time_zone = America/Toronto`: the colleague's change was silently reverted. This breaks BIC-21 ("nothing is overwritten") and §4 conflict. Fix: a three-way rebase that carries only the fields where `values ≠ old base` onto the new base. List only those fields as "Yours" in `ConflictNotice`. Add a check where the other save touches a *different* field (today T5 changes the same field only).
2. **(b) Closing the office panel (Close, Escape, ×, or after Save) does not close it; it comes back.** `offices-page.tsx:59` calls `navigate("/platform/offices")`. `workspace.tsx:106-107` `move()` then *focuses the list tab* and leaves this tab on `/platform/offices/:id`. Edit is `data-workspace-open`, so the normal path always has both tabs. Probe Q1: after Close the URL is the list and there is no dialog, but the tab "Office: …" stays. Clicking it reopens the panel (dialog count 1), and Escape repeats the same loop. The person cannot finish an edit except with the tab's ×. Fix: when the record's own panel closes, close its tab if another tab shows the list, or else replace this tab's path. The builder's line `check_pf31_multitab_browser.ts:137` ("the panel closes") checks only the URL and so passes; make it assert that the tab is gone.
3. **(c) The global ETag makes Express answer 304 with a stale body.** `platform/http/if-match.ts:50` sets `ETag = "<version>"` on every answer that has a top-level `version`. Express's `res.send` then replies 304 whenever `If-None-Match` matches, and browsers send that header themselves on a `fetch` cache revalidation. The firm profile's version covers only the firm row and the settings times, not `offices` or `licensedStaff`. Curl proof: GET → ETag `"c10494…"`. I added an office: the body now says `offices: 3`, but the version is unchanged, and a revalidation is **304** (the cached copy still says 2). Before this PR, Express's body-hash ETag stopped that. Fix: send the version ETag only when the version covers the whole body, or not on GET (keep it on the save's answer), or add `Cache-Control: no-store` to answers that carry it. Add a check that a GET with a changed body is never 304.

**Should**
4. **(b) Focus is lost.** Delete or × on a focused tab (`workspace.tsx:90-102`) and Alt+PageDown/Up (`:136`) leave `document.activeElement = BODY` (probes P3, P4). WCAG 2.4.3, and the study's own §5 says Delete "moves focus to the next one". Fix: focus the new active tab (strip) or its main heading.
5. **(b) ARIA tabs are incomplete.** No element has `role="tabpanel"` and no tab has `aria-controls` (probe P3: `[0,0]`; `workspace.tsx:174, 209`). The APG pattern the standard cites needs both. Fix: `role="tabpanel" aria-labelledby` on `data-ws-panel` and `aria-controls` on each tab.
6. **(b) The close × is a 20×20 px target** (`workspace.tsx:217`, `size-5`; probe Q1 `[20,20]`) at 768 px and wider, which fails WCAG 2.2 2.5.8 (24 px). A touch tablet at 1024 px has no other way to close a tab. Fix: `size-6` or larger.
7. **(b) The conflict state is neither announced nor focused.** `office-panel.tsx:78` tries to focus `[data-conflict]`, but probe K2 found focus is not on it, and `conflict.tsx:133` has no live role. A screen-reader user who presses Save hears nothing. Fix: `role="alert"` on the notice, or focus it after commit (an effect on `conflict`, not a rAF in the catch).
8. **(c) The person PATCH still saves with no version** (`people/edit.ts:61-66`, version optional), so a client that leaves it out gets last-write-wins. The study (`ux-multi-tab…md:40`) claims "routes that take a version already refuse a save without one (422)". That is false for this route. Make the version required (the web always sends it), or correct the sentence and record why it is optional.
9. **(a/b) Section numbers do not match.** The standard is EXPERIENCE **§2.13**, but the study (`ux-multi-tab…md:5, 43`) and the code headers (`workspace.tsx:1`, `drafts.tsx:1`, `if-match.ts:1`, `office-panel.tsx:6`, `multi-view.ts:1`, the check's line 1) say §2.12, which is "Accessible". (a) should also say in §2.13 or §4 that "keep mine" keeps only the fields I changed, which is the rule Must 1 breaks.
10. **(b) Ctrl-click on any same-origin link inside a staff frame becomes an in-app tab** (`workspace.tsx:125-131`), so it also catches links that are not app routes (an `/api/…` file link without `download`). Fix: open in-app tabs only for app routes and let other links behave normally.

## Code checks with no finding
Draft store: echoes do not loop (a remote write never reposts, `drafts.tsx:38`). The presence count is a Set per window, with an open-reply handshake and `pagehide` close. Hidden tabs keep Dialog and Panel closed (`controls.tsx`), so no focus trap and no `pointer-events:none` leaks (P4). Interceptor: the guard runs first. A header plus an absent or empty body fills the version. A body version that differs, `*`, `W/` or a list gives 422. If-Match on a route without a version gives 422 (T9). Back/Forward follow the tab that shows the address (P5). Graph: G3 lists `PATCH /platform/offices/:id` and `PATCH /front-office/people/:personId` as untested, but `check_pf31` reaches both: the graph does not parse template URLs (tool gap, not a finding).
