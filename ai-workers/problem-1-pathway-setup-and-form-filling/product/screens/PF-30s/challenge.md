Challenger: a fresh agent that did not draft the concept (skill screen-concept B), 22 Nov. Read: `concept.md`, BACKLOG row PF-30s (line 1089), EXPERIENCE §2, §4, §5, STANDARDS §9; PF-30a on `origin/claude/runtime-pf30a` (#2884, not merged): `ports/find.ts`, `api/src/platform/find/routes.ts`, `api/src/front-office/find.ts`; web `components/frame.tsx`, `modules/platform/frame.tsx`, `modules/front-office/sales/sales-frame.tsx`, `modules/front-office/routes.tsx`. ## Objections

**Major**
1. **Fixed group order means Enter can open the wrong record (BR-3, BR-5; concept:16, :18).** The API sorts hits by rank across kinds (`front-office/find.ts:140`: exact number 1000, email or phone 900, name prefix 700, company prefix 650, a trigram name match up to 600) and groups them in order of first appearance (`ports/find.ts:109-114`). So the group order already *is* the ranking. The concept reorders groups into a fixed list and merges `person` with `prospect`. Example: typing "Park" returns the company "Park Holdings" (prefix, 650) and a person "Lena Parks" (trigram, ~300). In the concept's order the person comes first, so Enter opens the weaker match. Fix: keep the API's group order and its hit order, and use BR-3 only to give each kind its words. Enter opens the API's first hit.
2. **The kinds BR-3 names do not exist yet, and an unknown kind is hidden without anyone noticing (concept:16).** PF-30a returns only `person` (url `/front-office/leads/:id` or `/front-office/prospects/:id`), `prospect` and `company`. A company hit opens its *prospect* page (`find.ts:103-104, 117, 136`). `client`, `case` and `case_person` are guesses (CS-30c has no contract yet). If CS-30c registers `case_file`, its hits disappear without any test failing, and the "N results" count would no longer match the rows shown. Fix: map only the three real kinds now. An unknown kind fails the browser check (or logs a console error in dev). The count is the number of rows shown. The Clients, Cases and People on cases groups go into §6b as Not built, waiting for CS-30c.
3. **Two of the row's acceptance tests are dropped without saying so (concept:37 compared with BACKLOG:1089).** (a) "results within STANDARDS §9's budget on 100 Sample firms" (STANDARDS §9: search < 200 ms) is missing. (b) "type an email and open the client" and "type a case number and open the case" become a lead or prospect without being called Not built. Fix: add a timing check (time from typing to the list, with 100 Sample firms seeded, under 200 ms after the pause, or the time the API takes, measured separately). In §6b, name the client and case journeys as waiting for CS-30c.
4. **The box overflows sideways at 375 px (concept:24).** At 375 px the header row has 343 px (px-4, `frame.tsx:93`). The logo takes about 122 px (h-6, viewBox 314×62; shrink-0) plus a 12 px gap. PlatformFrame's controls are the name, which can shrink to 0, and Sign out, about 72 px (`platform/frame.tsx:95`). Add a 160 px box and 8 px gaps and the row needs about 382 px, which fails the concept's own 375 px check. A popover 28 rem wide anchored under the input also runs off the screen. Fix: below 640 px the box becomes a 44 px "Find" icon button (with an accessible name) that opens the input across the full header. "/" opens the same thing. Below 640 px the popover is fixed to the viewport (`inset-x-4`). Show the "/" hint as a separate `<kbd aria-hidden>` from `lg` up, not inside the placeholder text.
5. **Privacy: the browser can still store what was typed (concept:11, "never stored").** Without `autoComplete="off"` (plus `name` left out, `spellCheck={false}`), browsers keep the input's history and offer client names to the next person at the desk. The typed name also stays in the header after opening a record, and SalesFrame's sign-out clears only `["fo"]` queries (`sales-frame.tsx:60`). Fix: turn autocomplete off. Clear and close the box when a record is opened. Clear the box and its cache on sign-out and when the session ends: use query key `["fo","find",q]` and `gcTime: 0`, or plain fetch with no cache. Add the autocomplete attribute and the clear-on-open to the test.
6. **The combobox's keyboard and ARIA behaviour is not fully specified (concept:18, :24).** (a) "Enter opens the first when none is active" matches APG's list autocomplete *with automatic selection*. That pattern requires the first option to show as the Enter target (`aria-selected="true"` and a visible highlight). Otherwise Enter opens a row nobody can see. (b) Tab, Home and End, IME composition (`e.isComposing`: Enter must not open), and focus after Escape are not specified. (c) The "/" opener has no rules for modifiers, for open dialogs or drawers (EXPERIENCE §2.3 puts editing in drawers; focus must not leave an `aria-modal` that is open), or for `e.defaultPrevented`. Fix: write these down. Tab closes the list without opening anything. Ignore "/" when Ctrl, Meta or Alt is held, when a `[aria-modal="true"]` or `dialog[open]` is open, or while composing. Compare `e.key === "/"` (not `code`) so that other keyboard layouts work, and call `preventDefault` so neither the box nor Firefox's quick find receives the character. Options are not links: give each one an id `find-opt-<hit id>`.

**Minor**
7. **Partial result with no hits (BR-6, concept:19).** If `partial` is true and there are no groups, the box would show "No matches", which may not be true. Fix: show the partial line together with "No matches in what loaded."
8. **The subtitle claims a stage (BR-4, concept:17).** The API's subtitle is "Prospect P-00012", "Lost …", "Won …", "Lead …" or "Closed …" (`find.ts:34, 103-104`): a role and a number, never a stage name. The row asks for "role, case number and stage". Fix: render the subtitle exactly as sent, and list "stage name" as Not built (PF-30a's subtitle).
9. **Rules for matches and highlighting (BR-4).** `matched_on` is a list of 1 to 4 entries: show all of them ("Email, Phone"). Highlight only a match that ignores case and accents in the title, built from text nodes, never inner HTML. An email or phone match has nothing to highlight, and the row says so with its match word.
10. **Errors other than a failed search.** A 401 is already handled by `staffApi`, which ends the session (`platform/session.ts:82`), so the error line must not appear on top of it. While the terms page is shown, PlatformFrame still renders the controls (`platform/frame.tsx:95, 101`), so the box would get 428 errors: hide it while `pending.terms` is set. Cancel the older request (AbortController) in addition to BR-7's sequence check.
11. **The count line (EXPERIENCE §2.7).** One finder returns at most 8 hits (`ports/find.ts:16`). "8 results" reads as "all there is", so say "8 best matches. Type more to narrow" when the cap is reached. Keep "Searching…" visual only so screen readers do not hear it on every keystroke.

## What is sound
It reads only PF-30a's door, with no new API, data or engine. BR-8 refuses to show hidden counts and raises that as an open question instead of inventing a count (it is right: a count would tell view.own users that records exist). Putting the box in PlatformFrame and SalesFrame is justified: `modules.tsx` is a routes seam with no top bar, and those two frames cover every bearer-token staff page (booking, retainers, compliance and complaints all use PlatformFrame), with the box only when `who` is set. Leaving the Studio and Cases simulated-person frames out is honest (the door is `@AnyStaff`, `routes.ts:19`). "/" for the box and Cmd+K left alone follows AG-02. The kept-up-to-date and late-answer rules (BR-2, BR-7) match the API's 2 to 100 characters (`ports/find.ts:23`). The test name and the deviation from the row are explained.
