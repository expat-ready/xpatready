## 1. Job and journey
A case officer checks a client's uploaded file without downloading it: opens it from its checklist line, reads it page by page beside the case, and goes back to the line to decide. Persona: case officer and above on the case (the download's reach, `"officer"`; AG-9-53). Requirement text: **AG-9-24** "In-app preview (PDF/image) via short-lived signed GET; every preview is access-audited"; AG-9-16 (signed GETs, never public), AG-9-20 and AG-9-55 (never an unscanned file; "Checking for viruses…", "Removed — infected file"), AG-9-32 (every read leaves a record; here the one audit trail, CS-D6). Journey: client uploads (C6.4) → scan (PF-F3) → **officer previews** → accepts on the line (CS-D1 part 2) → Ready to file.

## 2. Layers (STANDARDS §2)
* **Masters, links, configuration, rules:** none new. The file belongs to `case_document` (C6.4); its scan state is PF-F3's (`FilesPort.scanState`) once CS-D1 part 1 moves case files onto `FilesPort`; the "contains scripts" flag is PF-F4's byte scan (`file-type.ts`, `SCRIPTS_FLAG`), recomputed on read until contract gap 2 is ruled (brief).
* **Engine / API on main:** `GET /api/runtime/documents/:id/file` (`case-documents.ts:719-724`) already serves inline with `nosniff`, `content-security-policy: default-src 'none'; sandbox`, `private, no-store`, and writes "viewed" (`:408`). Missing against AG-9-24: the short-lived link and the "previewed" line.
* **API new (part 1, the brief's):** `POST /api/runtime/documents/:id/preview-link` → `{ url, expires_at, media_type, file_name, size_bytes, uploaded_at, scan: "CLEAN", contains_scripts }`, 409 "Not available yet: still being checked." / 410 "Removed: unsafe file." with no link; `GET /api/runtime/document-previews/:token` (bytes, the download's four headers). One "previewed" audit line when the link is made.
* **Screen on main:** `web/src/runtime/checklist.tsx` lists each line's current file as text ("File: passport-scan.pdf"); no viewer. `documents-drawer.tsx` `OpenFile` (`:144-161`) opens the file in a new tab as a blob (fill-from-documents only; unchanged here). The team's kit has `Panel` (`components/ui/controls.tsx:100`, right side panel, max 560 px).
* **Screen new (part 2):** `web/src/runtime/document-preview.tsx` (`DocumentPreview`, in `Panel`), PDF.js (`pdfjs-dist`, through STANDARDS §1 and P-587; P-607 S3 Q9 "PDF.js, scripts off"), one entry point in `checklist.tsx`.
* **Team's code:** not in this cloud copy (`code/` absent); the brief asks the Lead to check on the Mac whether the team already ships a PDF viewer (STANDARDS §1: prefer what the team has). Unverified here.

## 3. Business rules
* **BR-1 Only a clean file opens** (AG-9-20, AG-9-55, SA8-D2): the viewer asks for a link; a file still scanning shows "Not available yet" and a removed one "Removed — infected file", with no link made and no bytes fetched.
* **BR-2 Short-lived, nameless link** (AG-9-24, AG-9-16): the link lives 5 minutes (Sample), is tied to the firm and the staff member who asked, and its URL holds no firm, person or file name. Bytes are fetched once into memory (`fetch` with the session header → `ArrayBuffer` for PDF.js, `Blob` URL for images, revoked on close); never an `<iframe>`, never the browser's own PDF plug-in.
* **BR-3 Nothing in the file runs** (P-607 S3 Q9, P-587): PDF.js draws to a canvas with `isEvalSupported: false`, scripting never enabled, no sandbox bundle shipped, the worker from our own origin; a version at or above the fix for CVE-2024-4367 (checked at the advisory on the day, in the gate note). A PDF flagged by PF-F4 shows "Contains scripts: opened only in the safe viewer" and still renders.
* **BR-4 Same reach as the download** (AG-9-53): who can open the download can preview; anyone else gets 404 in the download's words; a client gets whatever status the download gives a client today (measured, not changed).
* **BR-5 Every preview is recorded once** (AG-9-24, AG-9-32): one "previewed" line per opening (when the link is made); page turns, zoom and PDF.js's repeat fetches write nothing more; a refused opening writes nothing.
* **BR-6 View only** (row): page, zoom (Fit width, 100%, 200%) and rotate change the view, never the file or its record; closing forgets them.
* **BR-7 An expired link renews once**: a page turn after expiry asks for one new link (a second "previewed" line, an honest second opening); a second failure shows "This preview ended. Open it again from the line."
* **BR-8 Decide on the line** (row: accept and reject stay where they are, C6.4): the panel holds no Accept or Reject. Today neither exists for staff on `main` (the line states exist, no route sets them); CS-D1 part 2 adds Accept on the line; Reject with a reason has no row (question 1).

## 4. Layout (EXPERIENCE §3 "Side panel": the team's `Panel`, 560 px; board S1-S3)
* **Entry (S1):** on a line with a current file, the file name becomes a link-styled button, label "Preview passport-scan.pdf"; a set with several current files gets one button per file. Only current files (the History dialog's earlier files: not built, §6b).
* **Panel:** header = file name (wraps), then the document type and the person, type and size ("PDF · 412 KB"), "Uploaded 21 Nov 2026 by Client A", pill "Checked: clean" (tooltip "Scanned for viruses before it could be opened"). Toolbar: Previous page · "Page 1 of 3" (live region) · Next page · zoom segmented control (Fit width default) · "Rotate" (tooltip "Turns the view only; the file is not changed"). Body: the page, one page drawn at a time; the page area alone scrolls at 200%. Footer: Close only (no primary button: BR-8). Focus returns to the file-name button on close.
* **States (S2):** loading (a skeleton sheet, "Opening the file…") · not available yet (Try again) · removed · contains scripts (a warn notice above the page) · image (no page controls) · no preview for this type (for later types; question 2) · preview ended · could not open (sha mismatch or a PDF that fails to draw: "The file could not be opened. It may be damaged, or it changed since it was uploaded. Ask for it again.") · long names wrap · read-only by nature.
* **Phone (S3):** the panel takes the width; the toolbar wraps; no sideways page scroll. Keyboard: Tab through the toolbar; PageUp/PageDown turn pages when the page area has focus; Escape closes. 1024 px and 200 % zoom work.

## 4b. Best in class (vendor and project behaviour as remembered, not re-read for this concept: Unverified)
Mozilla's own PDF.js viewer: page number with total, previous/next, zoom presets including "Page Width", rotate, all keyboard-reachable. Google Drive and Box previews: a file opens over the list in place, name and size in the header, the list kept behind. Clio and Docketwise (immigration/legal case tools): document preview inside the matter, download as a separate action. **Copy:** the in-place panel and the PDF.js controls set. **Beat them:** the scan state said before anything opens, the "contains scripts" warning, a recorded opening, and no download needed to check a file. Effort saved: one click from the line, no file on the officer's computer to clean up later.

## 7. Questions (recommendation first)
1. **Reject with a reason has no row.** The row says "accept and reject-with-reason stay where they are (C6.4)", but on `main` staff have neither; CS-D1 part 2 adds only Accept (Lead B's ruling, #1877). **Recommend:** the tech lead adds "Reject with a reason" beside Accept in CS-D1 part 2 (or a CS-D1 part 2b), so the officer can act right after previewing; this concept does not build it. For the tech lead.
2. **Types beyond PDF, PNG and JPEG.** PF-F4 allows HEIC, TIFF, Word and Excel uploads elsewhere; `case_document` holds only PDF, PNG and JPEG today (SQL check), and `DocumentPdfPort.toPdf` (PF-Fp) could convert others. **Recommend:** R1 previews PDF, PNG and JPEG only, with the "No preview for this file type" state ready; conversion is a later row when case uploads widen. For the founder only if case uploads widen in R1.
3. **Where "contains scripts" is kept** (brief, contract gap 2): Lead B's ruling; until then part 1 recomputes it on read. For the tech lead, not the founder.
