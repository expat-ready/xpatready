## 1. Job and journey
* **Job:** see every LMIA file of the firm in the step it has reached, open one right first time, and walk it from set-up to workers.
* **Persona:** the case officer (card "Owner" = `CaseTeamMember OFFICER`, Lead 61). Keys: `agent/case:show` (read), `:create` (open, Re-apply, Create work permit case), `:edit` (job, positions, locations, channels, candidates, moves), `:waive-deficiency` (pass a CRITICAL), `:submit` (Record the submission), `:record-decision` (decision, Withdraw). A button whose key is missing is hidden; a forced call shows the server's 403 words.
* **Journey:** board → Open an LMIA file (board, or `/clients/:id` with the client picked) → employer + location → job → stream and positions (confirmed here, AG-17-5/-9) → Set-up (warnings) → Recruitment (channels, clock, candidates, ads and offer, report) → Record the submission → officer contacts → decision → workers → Create work permit case → the employer's client screen lists files and workers.

## 3. Business rules (the server decides; the screen shows)
* BR-1 Nine columns in AG-17-14's order; renamed labels show, order never changes; Closed hidden until "Show Closed (n)" (AG-17-18, -55). Columns of steps no row fills yet say "Built in CS-98s3" (Lead 61).
* BR-2 Current step, server-side: before submission the furthest step with a started item, up to Preparation & quality check (a worker named on a Requested position does not move it); after: submission → Submitted, decision → Decision, Workers & permits at the decision if an approved position has a worker else on the first worker assigned, Compliance on the first worker's start date (AG-17-18).
* BR-3 Card and List row (same data, AG-17-54): employer, occupation, location, stream, positions requested (· approved), owner, one next-due chip (nearest dated item; "No dated item yet"), open-CRITICAL count, Submitted waiting-on chips, "Placed manually".
* BR-4 Filters in the address: Mine and Step primary; More filters: owner, employer, stream, has CRITICAL, validity expiring (within the validity row's lead time; "Sample" while the row is), placed manually; Show Closed. Scoped by CS-K3's `caseScope`. No view toggle (PF-6vt); the board is never filtered by a view (AG17-D6).
* BR-5 Before submission a file moves forward only, by drag or "Move to step" (card and List row; later steps only); it shows "Placed manually by {name}, {date}" + "Back to automatic"; the mark clears when the computed step reaches it or on submission; no move after (AG-17-55; CS-98b override; the clear route is Q3).
* BR-6 A file shows only steps with items (AG-17-15), each Not started · In progress · Done · Not applicable (AG-17-17); What's next: the viewer's items, then the employer's, then others; by due date (undated last), then step; each with its reason and one link (AG-17-19). Both come from the server (Q2).
* BR-7 The stream is proposed from the wage-threshold row (value, source and date, or "Sample") and **confirmed in the wizard**; a stream the wage did not propose needs a reason; the file is bound at creation (AG-17-5, -8, -9; CS-98b). After opening, the stream is read-only; "Change stream" (before submission; closes this file "Stream changed", opens a linked one) arrives with CS-98b part 2 (AG-17-13). A later wage edit that proposes another stream is shown as a warning, never a silent change.
* BR-8 CRITICAL: the job's wage below the prevailing wage; refusal-to-process; low-wage cap; missing business number (AG-17-3, -10, -11). Where the release holds no prevailing wage, it and its source are a required field in the wizard, not a warning (AG-17-10). A CRITICAL passes with `:waive-deficiency` and a reason, never locks: "Passed by {name}, {date}: {reason}" naming the warning; MAJOR, MINOR and INFO: "Acknowledge" (CS-98b `ReadinessPass`). No un-pass.
* BR-9 Positions and job details change before submission only (server 409 words after); each position change re-runs the cap check and is on the timeline (AG-17-87).
* BR-10 Duplicate check (AG-17-95, CS-98b part 2): unsubmitted match → "Add positions to it" or "Open a separate file anyway" (audited); submitted → information; approved with unfilled positions → count and date; different stream → points to Change stream; a match the viewer can't open → "Ask a manager", no details. The open call answers the check (no separate read): "Add positions to it" goes to that file; "Open a separate file anyway" resends the open with `openSeparate: true`, audited. Warns, never blocks.
* BR-11 Recruitment (CS-98c): clock "day X of Y" for the least-advanced required channel; channel states not started · running · minimum met · window closing · expired (CRITICAL) · satisfied; earliest recruitment-complete and latest submission dates; candidates one per applicant (same-name offer), missing rejection reasons → one combined CRITICAL; staff only (AG-17-23..30); ads and offer pre-filled from the job, a wage, hours or location difference → CRITICAL naming field and document, one `dutiesMatch` tick (AG-17-32).
* BR-12 (s2) Record the submission: date, application number ("Sample label"), the submitted copy uploaded, other documents, submitter (AG-17-36); not signed off → one confirmation on 409 `SIGN_OFF_CONFIRM` (AG17-D46). Decision: Approved or Refused (root cause optional), letter, ESDC's decision number as its own field (Lead 61), approved count then which positions are not approved, Save off until the counts match, the server's 400 still shown (AG-17-39, -41). Withdraw in the header on every step until a decision, with date, reason, optional letter (AG-17-89). Validity "Sample" with no reminder line while Sample (P-412 F13 (b)). Re-apply after refusal or withdrawal, linked, optional copy (AG-17-41).
* BR-13 (s2) Create work permit case: only on an approved position with a worker, once (409 shown); the Individual combination chosen (pre-chosen Work permits › Employer-specific › With an LMIA, Sample); facts copied once, never live; counts as one individual case; plan limit refused in place (AG-17-43, -45; CS-98e). The worker never sees the LMIA file.
