## 1. Job and journey
* **Job:** see every LMIA file of the firm in the step it has reached, open one, and get its set-up and recruitment right before anything is filed.
* **Persona:** the case officer (the card's "Owner", `CaseTeamMember OFFICER`, Lead 61 ruling) at a firm (keys `agent/case:create`, `agent/case:edit`, `agent/case:waive-deficiency`; AG17-D28: no new key). The employer sees nothing here (AG-17-30).
* **Journey (J-98 LMIA half):** Cases › LMIA board → "Open an LMIA file" (from the board, or from a company client's page with the client picked) → employer + location → job → stream proposed from the wage table → confirm stream, positions, duplicate warning → the file opens in Set-up → resolve or waive warnings → log channels, watch "day X of Y" → record candidates → download the recruitment report → the card moves to Advertising & recruitment by itself → (CS-98s2) submit, record officer contacts, record the decision with positions approved → assign workers → "Create work permit case" lands on the worker's case → the employer's client screen lists its files and workers.
* SA-01B ids: not known (AG-17 cites SA-1B-50/51 for client type only).

## 3. Business rules (the server decides; the screen shows)
* BR-1 Columns are the nine journey steps in AG-17-14's order; a firm's renamed labels show, order never changes (AG-17-55). Closed column hidden by default, shown by "Show Closed (n)" (AG-17-18).
* BR-2 A card sits in the file's **current step**: before submission the furthest step with a started item, up to Preparation & quality check; naming a worker on a Requested position does not move it (AG-17-18). Computed on the server, never in the browser.
* BR-3 A card shows employer, occupation, positions requested (and approved once decided), owner, one "next due" chip (nearest dated item), the open-CRITICAL count; Submitted cards add waiting-on chips (AG-17-54). The List shows the same data.
* BR-4 Filters: Mine, owner (the case officer), employer, stream, step, has CRITICAL, validity expiring, Placed manually, Show Closed (AG-17-55); in the address; scoped by CS-K3's `caseScope` (a `view.own` holder sees their team's files). No view toggle here (PF-6vt, ruled); the board is never filtered by a view (AG17-D6).
* BR-4b Before submission a card moves **forward only**, by drag or by "Move to step" (keyboard, screen reader, touch); it then shows "Placed manually by {name}, {date}" and "Back to automatic"; the mark clears itself when the computed step reaches it or on submission; after submission no move (AG-17-55; CS-98b's override, 409 otherwise).
* BR-5 A file shows only steps that have items (AG-17-15), each Not started · In progress · Done · Not applicable (AG-17-17).
* BR-6 "What's next": the viewer's own items first, then the employer's, then others; by due date (undated last), then step order; each with its reason and one link (AG-17-19).
* BR-7 Stream: proposed from the release's wage-threshold row for the location's province on the entry date, showing value, source, date checked or "Sample" (AG-17-8); bound only when staff confirm; a stream the wage did not propose needs a reason (AG-17-9).
* BR-8 Warnings: prevailing wage below the job's wage, refusal-to-process, low-wage cap, missing business number are CRITICAL; each is passed with `agent/case:waive-deficiency` and a reason, never locks; a passed one reads "Passed by {name}, {date}: {reason}" (AG-17-3, -10, -11; CS-98b's `ReadinessPass`). Where the release holds no prevailing wage, it is a required field, not a warning (AG-17-10).
* BR-9 Positions added or removed before submission only; each change re-runs the cap check and is on the timeline (AG-17-87). Change stream before submission only (AG-17-13).
* BR-10 Duplicate check on open (employer, occupation, location): warns, never blocks (AG-17-95).
* BR-11 Clock "day X of Y" for the least-advanced required channel; channel status not started · running · minimum met · window closing · expired (CRITICAL) · satisfied; earliest recruitment-complete and latest submission dates from the server (AG-17-23, -24).
* BR-12 Candidates: one entry per applicant (a same-name entry asks first); missing rejection reasons give **one** combined CRITICAL (AG-17-26, -27). Staff only (AG-17-30).
* BR-13 Every LMIA value without a citation shows "Sample" with its tooltip (CS-98r; AGENTS rule 4); a cited one shows its source and date.
* BR-14 (s2) Submit without sign-off asks once on the server's 409 `SIGN_OFF_CONFIRM`, never a disabled button (AG17-D46). Decision: approved count, then which positions are not approved; Save stays off until the counts match; the server's 400 still shows (AG-17-39). ESDC's decision number is its own field (Lead 61). Withdraw only before a decision (AG-17-89). Re-apply after refusal or withdrawal, linked (AG-17-41). Validity "Sample" with no reminder line while Sample (P-412 F13 (b)).
* BR-15 (s2) "Create work permit case" only on an approved position with a worker; once per position (409 shown); it lands on the worker's individual case with employer facts shown as copied (AG-17-43, -45; C1.3). The worker never sees the LMIA file.
* BR-16 (s2) Corporate panels sit on the staff client screen, not a separate screen; a missing panel says "Not built yet", named (AG-17-57, AG-7-86, Lead 62).

## 4. Layout (`design/layout.html`)
* **Board (boards 1, 8):** Library list header (title, one-line subtitle, Board/List switch, the one filled button "Open an LMIA file"), filter row, nine columns that scroll inside the board, never the page. Card link opens the file. Copies Pipeline's board, its "Load more" per column (200 cards) and its List-first accessibility.
* **List (board 2):** same columns as data; sorted by next due; the keyboard and screen-reader route.
* **Open an LMIA file (board 3):** Dialog / wizard pattern, right panel 520 px, 3 steps: Employer (company client, location from its locations; "Add a location" is the client's) · Job (occupation from the release's list, wage, hours, overtime rule, duties, start, duration; the stream proposal shows live once province and wage are known) · Stream and positions (radio with the proposal pre-chosen; reason field only when another is chosen; positions; duplicate warning; "Will be created as …"). Primary: "Open the LMIA file".
* **File (boards 4, 5, 9, 10):** Workspace pattern, module page `/case-delivery/corporate/files/:id` (brief's recommended option; a link line on the case page of a Corporate combination). Header: employer · occupation, file number, location, positions, owner, current step, stream chip. Left: steps with items and status (task list, BIC-10). Right: What's next, then the step's panels. Set-up: Stream (primary "Confirm High-wage" until confirmed), Job details (edit in a drawer), Positions, Warnings (waive in a drawer; a waived one shows who, when, reason, "Undo the waive"). Recruitment: clock strip, Channels (primary "Log a channel"), Candidates, Recruitment report. (s2) Submitted: submission, officer contacts with respond-by and task, "Record the decision" drawer, Withdraw in the header before a decision. Workers & permits: validity strip, positions with worker, milestones, "Create work permit case"; Re-apply panel after refusal/withdrawal. Steps not built by any row yet (Employer onboarding, Employer documents, Preparation & quality check, Compliance) are marked "Built in CS-98s3" (Lead 61).
* **Corporate panels (board 11, s2 part 2):** employer profile and locations, LMIA files with step, workers with milestones; contacts/seats, employer documents, billing: "Not built yet". Waits on the staff client screen (contract gap, CS-98s2 brief).
* **Drawers (board 6):** waive, edit job, add position, log channel, record candidate: Side panel pattern, Cancel left, primary right, field errors on the field + summary.
* **States (board 7):** empty, nothing matches, loading skeleton, error with Try again, 403, 404 (same words for another firm's file), read-only after submission, Sample marker, long content. 375/1024/1440 with no page scroll.
* Routes: `/case-delivery/corporate` (board, `?view=list&mine=1&owner=&employer=&stream=&step=&critical=1&expiring=1&placed=1&closed=1`), `/case-delivery/corporate/files/:id` (file, `#setup`, `#recruitment`, `#submitted`, `#decision`, `#workers`). Reached from the menu until PF-6vt lands.

## 6. Contract and tests
Every write and the file reads are CS-98b..e's routes (`/api/runtime/cases/:id/corporate/…`, `/api/runtime/clients/:id/corporate/…`; stream proposal is a read, `POST …/corporate/stream-proposal`). The screens add one read, CS-98s1 part 1's own (brief), paged on the server, scoped by `caseScope`:
* `GET /api/runtime/corporate/board?{filters}` → `{ columns: [{ step, label, count, cards: [{ caseId, fileNumber, employer, occupation, location, stream: {key, confirmed}, positionsRequested, positionsApproved|null, owner, nextDue: {label, date}|null, criticalOpen, waitingOn: [label], placedManually: {by, at}|null }] , next|null }], closedCount, filters: { owners, employers, streams } }` (the current step from CS-98b's exported function).
* The file page reads, one per step, CS-98b/c/d/e's replies, together giving `{ header, steps: [{ step, label, status }], currentStep, whatsNext: [{ who, label, reason, due|null, link }], setup: { job, stream: { proposed, confirmed, threshold: { value, province, effective, source|null, sample } }, positions, warnings: [{ code, severity, words, waived: {by, at, reason}|null }] }, recruitment: { clock: { day, of, channel, sample }, earliestComplete, latestSubmission, channels, candidates, combinedWarnings } }`.
**Journeys** use the briefs' names (`tests/check_cs98s1_lmia_browser.ts` DW1–DW6 + W1; `tests/check_cs98s2_lmia_browser.ts` DW1–DW6 + W1), seeded through CS-98b..e's API, live AI off. This concept adds the drawn checks below to those, mapped in the build PRs:
* DW1 open a file from a company client with 3 positions (pass); a non-company client is not offered and a forced Individual combination answers the server's refusal (fail).
* DW2 confirm the proposed stream (pass); choose the other stream without a reason → field error, nothing saved (fail).
* DW3 waive a CRITICAL warning with a reason, count on the card drops by one (pass); empty reason refused (fail).
* DW4 log a channel and see "day X of Y" on a fixed clock (pass); an expired channel shows "Expired … CRITICAL" (fail case drawn).
* DW5 record a rejected candidate with a reason (pass); two without reasons give one combined warning, not two (fail).
* DW6 download the report: a PDF saved on the file (pass); a client-portal session reading candidates → refused (fail).
* DW7 board: card in the computed column, filters in the address, Mine + has CRITICAL narrow it; another firm's file id → 404 words. List equals board. Move to step forward → "Placed manually"; backwards not offered; gone after submission.
* (s2) record 3 of 4 approved choosing the not-approved one; 5 of 4 → server message; Withdraw gone after the decision; Create work permit case once, the second → 409 words; Sample validity has no reminder line.
* Keyboard-only through DW1–DW5; axe-core on each state; 375/1024/1440 with no page scroll; a Sample value always shows "Sample".
