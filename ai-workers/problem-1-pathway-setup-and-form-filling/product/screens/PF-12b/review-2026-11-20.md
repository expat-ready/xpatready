## Findings

**M1 (Major): a won prospect that keeps failing writes a `platform.bypass` line to its firm's append-only trail on every poll, with no end.**
- Cause: `live.ts:60` makes a new `touchedEach` each run, and `live.ts:31` writes the firm's line before the prospect is tried. The query
  (`prospect-won.ts:119-128`) lists that prospect again every run until a client exists. A failure is only pushed to `failed` (`:132`); there is no try
  count and no end state.
- Failing scenario: put a `prospect.won` for firm A in the outbox whose payload names firm B; `makeClient` throws at `prospect-won.ts:64`. Run `tick()` N times.
  - Expected: one line per crossing, with the retries bounded.
  - Actual: N lines in A's trail, at the default 10 s (`live.ts:23`, down to 200 ms). That is 8,640 lines a day per stuck prospect, for good.
  - The breaker reproduced it independently (break-report-2026-11-20 C4/C5).
- Why Major, and not the accepted m5:
  - m5's sweep writes 1,440 a day at most, and it is bounded: a cap-held row goes out the next day, and a platform row ends FAILED after 5 tries.
  - This has no bound. AUD-4 shows every line to the firm. After about 11.6 days every export over the period is refused 413 (`firm-read/service.ts:25`,
    EXPORT_MAX 100,000). QA-499's "uses × firms" count also grows with time.
- Fix: bound the retry. For example, a back-off kept across runs, or skip a prospect that failed until its wait ends, so that no line is written for it.
  Add a pass test and a fail test: N runs of a failing prospect write at most the bounded count.

**m1 (Minor): the runtime "only a none use may nest" check is untested.** Remove `entry.audit.startsWith("none: ")` from `firm-scope.ts:171`
and all 48 pass. The test at :140-144 checks the list statically. Fail test: set the (unfrozen) entry's `audit` to `"per-firm"` for one call and expect BypassRefused.

**m2 (Minor; STANDARDS §1.10): sign-up's known path has no fail test, and its order is not checked.** Two mutations pass all 48:
- `signup.ts:144` moved after the email.
- `.catch(() => {})` added to it.

The DW4 name at test :234 says "before the email", but the check reads only the count. The real-mail check at :337 asserts `!== knownLines`, not "A +1". The breaker's S2 shows the behaviour itself holds.
Add a check where A's line fails and no "already" row is written, and assert `${A}:n+1`. Verify's `:190` line has no test either (carried from 865df8f2e).

**m3 (Minor; pre-existing on main, PF-19p): `platform.account.mail` is `outside: true`** (`firm-scope.ts:121`). `withFirm(A, () => asBypass("platform.account.mail", …))`
opens BYPASSRLS from a firm's job. `inside` limits it only under another bypass. No caller needs `outside`: the background step keeps its route, and `direct`
covers suites. Dropping it would make the "one pair" claim complete.
